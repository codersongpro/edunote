# EduNote 개발 일지

작성 기준: 2026년 7월 5일
작성 목적: 개발 보고서 작성용 요약 자료
대상 범위: 초기 구현부터 v1.25.0 릴리즈까지

## 1. 개발 개요

EduNote는 교사의 학생기록 작성, 교무행정 문서 작성, 수업자료 제작, 업무 추출을 하나의 데스크톱 앱에서 처리하기 위해 개발한 교육 업무 보조 도구이다. 초기 버전은 학생기록 AI와 교무 AI 기능을 중심으로 출발했으며, 이후 실제 학교 업무 흐름에 맞추어 수업자료 생성, 자료실, 학생 메모, 공문 요약, 캘린더 연동, 나만의 AI 스킬 만들기, HTML 앱 제작, 릴리즈 자동화 기능을 단계적으로 확장하였다.

개발 과정은 사용자가 실제로 앱을 실행하며 발견한 불편을 빠르게 반영하는 방식으로 진행되었다. 특히 Windows 환경에서 바로 실행할 수 있는 portable EXE 배포, API 키 사용성, 다크모드, 생성 중단, 동시 생성, 학교 현장 문서 양식 개선에 중점을 두었다.

### 1.1 업데이트 의도

EduNote의 업데이트는 단순 기능 추가보다 교사의 실제 업무 흐름을 줄이고, 생성 결과물을 학교 현장에서 바로 검토·수정할 수 있는 수준으로 다듬는 데 목적을 두었다. 초기에는 학생기록과 교무행정 문서 작성 보조에 집중했으나, 이후 수업자료 제작, 업무추출, 자료관리, 백업, 교육용 게임 실행 등 교사가 하루 업무 안에서 반복적으로 수행하는 작업을 하나의 앱 안에 모으는 방향으로 확장하였다.

주요 업데이트 의도는 다음과 같다.

- 학생기록, 상담, 수업관찰, 창체, 교과세특 작성 과정에서 교사가 문장 초안을 빠르게 확보할 수 있도록 지원
- 공문서, 계획서, 보고서, 품의서, 회의록, 공고문 등 학교 업무 문서의 형식과 문체를 실제 행정 문서에 가깝게 정리
- 수업자료 생성 결과를 슬라이드, 워크시트, 퀴즈, 수업 계획서, 교육용 게임 등 바로 활용 가능한 형태로 제공
- 학생 명단과 개인정보가 불필요한 기능에 자동 반영되지 않도록 제한하여 개인정보 최소화 원칙 반영
- 생성 결과물에서 AI가 작성한 느낌, 반복 문구, 불필요한 기호, 어색한 문체를 줄여 공적 문서 품질 개선
- Windows 교사 PC에서 설치 부담 없이 실행할 수 있도록 portable EXE 방식의 배포 유지

## 2. 사용 프로그래밍 언어 및 기술 스택

EduNote는 Windows 환경에서 교사가 별도 서버 구축 없이 실행할 수 있는 데스크톱 애플리케이션을 목표로 개발하였다. 이를 위해 웹 기반 UI의 빠른 개발성과 데스크톱 앱의 파일 저장·로컬 데이터 접근 기능을 함께 활용할 수 있는 Electron 기반 구조를 채택하였다.

### 2.3 프론트엔드 및 사용자 인터페이스

프론트엔드는 React 19와 TypeScript를 기반으로 구성하였다. 학생기록AI, 교무행정AI, 수업자료AI를 각각 독립 화면으로 나누고, 사용자가 메뉴를 이동해도 생성 작업이 유지되도록 상태 관리 구조를 설계하였다. 아이콘은 lucide-react를 사용해 메뉴, 버튼, 상태 표시를 직관적으로 표현하였다.

화면 스타일은 Tailwind CSS와 PostCSS를 사용하였다. 다크모드, 반응형 레이아웃, 입력 폼, 탭, 버튼, 알림 배지 등 반복되는 UI 요소를 일관된 스타일로 유지하는 데 활용하였다. 사이드바 메뉴는 섹션별로 드래그하여 순서를 변경할 수 있으며, 변경된 순서는 localStorage에 저장된다.

### 2.4 데스크톱 앱 구조

앱은 Electron 30 기반으로 구성하였다. Electron의 main process는 파일 저장, 폴더 선택, PDF 생성, 웹페이지 메타데이터 수집, 로컬 데이터 백업 같은 운영체제 연동 기능을 담당한다. renderer process는 React 화면과 사용자 상호작용을 담당하며, preload script를 통해 안전하게 Electron IPC 기능에 접근하도록 구성하였다.

### 2.5 AI 및 생성 서비스

AI 생성 기능은 Google Gemini API와 `@google/genai` 라이브러리를 기반으로 구현하였다. 무료 등급에는 `gemini-2.5-flash-lite`, 유료 등급에는 `gemini-2.5-pro` 모델을 사용한다. 학생기록, 교무행정 문서, 수업자료, 공문 요약, 이미지 생성 요청을 각각 다른 프롬프트와 시스템 지침으로 분리하였다.

### 2.6 로컬 데이터와 백업

사용자 설정은 electron-store를 활용해 로컬에 저장하였다. 학생 명단, 나만의 자료실, 학생 메모 등 계속 불러와야 하는 자료는 JSON 파일로 관리하였다. 전체 자료 백업 기능으로 기본 정보, 학생 명단, 자료실, 메모 데이터를 하나의 JSON 파일로 내보내고 다른 컴퓨터에서 불러올 수 있다. Gemini API 키는 백업 파일에 포함하지 않도록 설계하였다.

### 2.7 문서 생성 및 파일 처리

PDF 저장은 Electron의 `printToPDF` 기능을 활용하였다. HWPX 관련 실험에는 JSZip과 `@xmldom/xmldom`을 사용해 문서 내부 XML 구조를 분석하고 템플릿 치환 가능성을 검토하였다. HWPX 기능은 문서 구조 보존 안정성이 충분히 확보되기 전까지 `(구현중)`으로 표시하도록 정리하였다.

### 2.8 빌드와 배포

개발 빌드는 electron-vite와 Vite를 사용하였다. Windows 배포 파일은 electron-builder를 통해 portable EXE 형태로 패키징하였다. Git과 GitHub를 사용해 버전별 변경 이력을 관리했으며, 릴리즈 파일은 로컬에서 실제 EXE 빌드 검증 후 GitHub Releases에 직접 업로드하는 방식으로 운영하였다.

## 4. 주요 개발 성과

### 4.1 교사 업무 흐름 중심의 기능 통합

EduNote는 학생기록 작성, 상담일지, 수업관찰기록, 공문서 작성, 수업자료 생성, 업무추출을 하나의 앱 안에서 연결했다. 교사가 여러 웹서비스와 문서 도구를 오가며 처리하던 업무를 한 화면에서 시작하고 결과를 저장할 수 있도록 구성했다.

### 4.2 학교 현장 문서 양식 반영

공문서 작성기에는 공문, 계획서, 보고서, 품의서, 회의록, 홍보자료, 가정통신문, 문자 및 소통메시지, 공고문 등 학교에서 자주 쓰는 문서 유형을 반영했다. 공문서·품의서는 합쇼체, 계획서·보고서는 보고서체 문체를 분리하여 각 문서 유형에 맞는 언어 품질을 확보했다.

### 4.3 수업자료 제작 기능 확장

수업 슬라이드, 워크시트, 퀴즈, 수업 계획서를 생성하도록 확장했다. 생성 결과는 편집 가능하도록 개선했고, 수업 계획서는 표 중심으로 출력되도록 하여 인쇄와 검토에 적합하게 정리했다. 퀴즈는 객관식·주관식·OX 유형을 체크박스로 선택할 수 있으며, JSON 데이터와 고정 템플릿 방식으로 생성하여 모든 유형이 항상 안정적으로 동작한다.

### 4.4 개인정보와 사용자 통제 강화

학생 명단은 필요한 기능에서만 사용하도록 조정했다. 수업자료 생성의 추가 요청사항에는 학생 명단이 자동 입력되지 않으며, 사용자가 직접 불러왔을 때만 반영되도록 했다. 공문서 작성기에서는 학년도, 날짜, 소속기관만 문맥상 필요한 경우 참고하도록 제한했다.

### 4.5 나만의 AI 스킬 기능 추가

v1.10.0부터 교사가 코드 없이 직접 AI 작업 패턴을 만들 수 있는 '내 스킬' 기능을 추가했다. 3단계 위저드로 입력 필드와 프롬프트 템플릿을 구성하거나, AI와 대화하면 자동으로 스킬 초안이 생성된다. v1.10.1에서는 HTML 앱 제작 기능을 추가하여 팀 점수판·수업 타이머 같은 인터랙티브 앱을 설명만으로 만들 수 있게 되었다. 스킬은 JSON 파일로 내보내고 가져올 수 있으며, 공유 마켓을 통해 동료 교사와 나눌 수 있다.

### 4.6 배포와 유지보수 체계 정비

Windows 사용자가 별도 설치 없이 실행할 수 있도록 portable EXE 배포 방식을 유지했다. v1.10.0부터 main 브랜치에 `package.json`이 변경된 상태로 push되면 GitHub Actions가 Windows EXE를 자동 빌드하고 릴리즈를 생성 또는 갱신한다.

## 5. 최근 릴리즈 요약

v1.9.0은 사이드바 구조를 정리한 릴리즈이다. 교사 기록·수업 도구 메뉴를 탭 형태로 통합하고, 설정·Demo 버튼을 사이드바 하단에 배치하였다. 메세지 메뉴를 탭 구조로 개선하여 SMS와 소통메세지를 한 화면에서 선택할 수 있게 하였다.

v1.9.1은 사이드바 트리 메뉴를 개선한 릴리즈이다. 생기부도우미·우리반기록·수업 도구를 펼침/접힘 트리로 분리하여 메뉴 탐색을 명확하게 하였다.

v1.9.2는 수업자료 기능을 높인 릴리즈이다. 워크시트 제목 정렬 강화, AI 이미지 삽입 기능 추가, Demo 창을 별도 창으로 분리하였다. 모든 생성물의 날짜·학년도 기준을 현재 날짜로 자동 통일하였다.

v1.10.0은 내 스킬(AI스킬즈) 기능을 신규 추가한 릴리즈이다. 3단계 위저드 또는 AI 대화형으로 프롬프트 스킬을 만들고, 파일 첨부·배치 처리·타임아웃·취소 기능을 갖춘 실행 화면을 제공한다. 마켓플레이스와 JSON 파일 공유로 동료 교사와 스킬을 나눌 수 있다.

v1.10.1은 스킬 기능을 확장하고 안정성을 높인 릴리즈이다. AI에게 설명하면 HTML 앱(팀 점수판·수업 타이머 등)을 즉시 만들어 주는 기능을 추가하였다. 수업 타이머 샘플 앱이 내장되어 있어 바로 사용할 수 있다. 사이드바와 탭 이름을 '내 스킬'로 통일하고, 스킬 카드에 `<앱>`/`<AI>` 뱃지를 추가하였다. 학교급 설정이 스킬 실행 결과에 자동 반영되며, 기본 테마가 다크모드로 변경되었다.

이후 패치에서 HTML 앱 입력 필드를 앱 이름·기능 목록·추가 요청 세 항목으로 구조화하고, 외부 CDN·ES 모듈·localStorage 등을 금지하는 생성 규칙을 보강하여 앱 생성 성공률을 높였다. 기존 데이터가 있는 사용자에게도 누락된 샘플 스킬이 자동으로 추가되도록 초기화 로직을 수정하였다. 학생기록 AI 화면에서 다른 메뉴의 생성 상태가 입력 패널을 잠그던 버그를 수정하였다. 내 스킬 실행·HTML 앱 화면에 autoFocus를 추가하여 화면 전환 즉시 키보드 입력이 가능하도록 개선하고, API 키 비활성화 시 안내 배너를 표시하도록 하였다. HTML 앱 카드에 수정 버튼을 추가하고, {{teacher_name}}·{{institution}}·{{school_level}} 시스템 변수를 프롬프트 템플릿에서 사용할 수 있도록 지원하였다.

v1.10.3은 보안과 생성 결과 검토 흐름을 강화한 릴리즈이다. API 키 노출 방지, HTTPS 연결 제한, 외부 도구의 JSON·HTML 검증, sanitizer 적용으로 보안 수준을 높였다. 생성 결과 화면에 교사 검토 체크리스트를 추가하여 개인정보·과장 표현·금지 표현·최신 지침 등을 점검할 수 있게 하였고, 빠른 재작성 버튼으로 더 짧게·더 공문답게·더 따뜻하게·중복 줄이기·NEIS 다듬기 등을 바로 요청할 수 있도록 하였다. 개인정보 보호 모드를 추가하여 AI 요청 전 학생 이름을 임시 토큰으로 치환하고 응답을 받은 뒤 원래 이름으로 복원하도록 하였다. 학생 메모를 학생기록 생성 시 참고자료로 연결할 수 있게 하였다.

v1.10.4는 저장·복사 UX를 단순화한 릴리즈이다. HWPX 직접 저장 메뉴를 제거하여 HWPX 양식 채우기 경우에만 표시되도록 하고, 편집 영역 강제 포커스를 제거하였다. 저장 버튼을 하나로 통합하여 PDF·Word·HWP·HTML·MD를 선택해 저장할 수 있게 하고, 복사 버튼도 HWP/웹 복사·Excel로 복사·MD로 복사로 통합하였다. 생성 결과 히스토리를 정리하고, 이수증 수집기의 파일 수를 10개로 제한하고 재실행 시 초기화되도록 개선하였다.

v1.11.4는 예산 작성 흐름을 단순화한 릴리즈이다. 교무행정AI의 '예산사용계획' 메뉴 이름을 '예산안작성'으로 변경하였다. 기존에는 왼쪽 입력 영역의 '예산안 만들기'로 빈 예산안 틀을 만든 뒤, 다시 상단의 '예산안 만들기' 버튼을 눌러 품목을 생성하는 2단계 구조였는데, 이를 입력 영역의 '예산안 만들기' 버튼 하나로 통합하여 예산안 틀 생성과 품목 자동 생성(AI 또는 내장 후보)이 한 번에 이루어지도록 하였다. 상단의 중복 버튼은 제거하였다. 또한 자동 생성·단가 추정 로직과 내장 품목 단가를 1만원(만원) 단위 중심으로 정돈하고, 만원 단위로 만들기 어려운 소액 소모품에 한해 천원 단위를 사용하도록 하였다. 다만 잔액을 0원에 가깝게 맞추는 채움 품목은 정밀 조정을 위해 기존의 소액 단위를 그대로 유지한다.

같은 릴리즈에서 '0원 맞추기' 기능을 변경 최소화 방식으로 재구현하였다. 사용자가 직접 수정하거나 잠근 행은 그대로 고정한 채, 나머지 행은 현재 수량을 최대한 유지하면서 단가가 큰 품목 위주로 수량을 최소한만 조정해 전체 예산 총액의 잔액을 0원에 맞춘다. 품목마다 최소·최대 수량을 지정하면 그 범위 안에서만 조정하며, 정확히 0이 되지 않을 때는 잔액이 초과되지 않는 선에서 0에 최대한 가깝게 줄이고 남는 끝자리 금액은 소액 품목으로 채운다. 또한 하위 항목을 가진 부모(묶음) 행의 규격 칸에 표시되던 '묶음' 문구를 제거하여 표를 더 깔끔하게 정리하였다. 과목별 비율을 따로 입력하지 않아도 예산안을 만들 수 있도록 하였으며, 비율이 비어 있을 때는 업무추진비를 총 예산의 3%로 배정하고 나머지를 교육운영비·일반운영비에 자동 배분한다.

또한 그동안 안내 문구로만 약속돼 있고 실제로는 빠져 있던 '인터넷 가격 조회' 기능을 구현하였다. 예산안 화면 위쪽에 검색 패널을 추가하여, 입력해 둔 나라장터·네이버 쇼핑 키로 키워드를 검색하면 실제 상품명·규격·단가·출처 링크를 목록으로 보여주고, 항목을 누르면 선택한 과목에 품목으로 바로 추가한다(단가와 출처가 자동 입력됨).

또한 공문서 작성기의 미리보기에서 한글 제목과 본문이 글자 중간에서 어색하게 줄바꿈되던 문제를, 예시 미리보기·생성 결과·저장(PDF·HTML·Word) 문서 모두에 `word-break: keep-all`(어절 단위 줄바꿈)을 적용하여 해결하였다. 아울러 계획서 예시에 포함돼 있던 폐지 사업 'AI 디지털교과서(AIDT)' 관련 문구를 제거하였다.

v1.11.5는 예산안작성의 표를 과목 중심 트리로 개편한 릴리즈이다. 교육운영비·일반운영비·업무추진비 과목을 트리의 1단계 루트 행으로 두어, 모두 접으면 과목 세 줄만 보이고 펼치면 '과목 > 품목'의 2단계로 표시되며 필요 시 3단계까지 직접 구성할 수 있도록 하였다. 자동으로 생기던 '세부' 중간 단계를 없앴고, 과목과 상위(하위 항목을 가진) 행은 규격·단가·수량 칸을 비우고 소계만 하위 합계로 표시한다. '모두 접기/펼치기'와 '과목별 정렬' 버튼을 추가하였으며, 산만하던 행 추가 방식을 정리해 각 과목 행의 '+ 품목' 버튼으로 품목을 추가하도록 단순화하였다(품목 행에는 세부 항목 추가 아이콘만 둔다). 인터넷 가격 조회로 추가한 품목은 해당 과목 맨 위에 삽입되고, 검색 결과에 마우스를 올리면 상품 이미지를 미리보기로 보여준다(외부 이미지는 data URI로 변환해 CSP를 우회). CSV로 내려받을 때도 화면에서 보이는 트리 모양(과목·들여쓰기·상위 행 빈칸)과 동일하게 저장·복원되도록 하였다.

v1.12.0은 예산안작성의 작성 방식 선택과 패널 접기 UX를 정리한 릴리즈이다. 예산안을 만들기 전에 과목별 비율 방식과 일반 작성 방식을 선택할 수 있게 하였고, 일반 작성 방식은 예산 과목 없이 품목 중심으로 작성되며 예산 과목 칸을 빈칸으로 표시한다. 예산 제목·금액·구입 물품 입력칸은 회색 예시 문구로 안내하고, 저장한 예산안과 입력값은 앱을 다시 실행해도 유지되도록 하였다. 저장된 계획 목록에는 저장 날짜와 시간이 표시된다. 예산안 생성 완료 시 기존 생성 완료 효과음과 같은 소리가 나며, 최소·최대 수량은 필요한 경우에만 입력하면 된다는 안내를 추가하였다. 또한 메인 사이드바와 각 기능 화면의 하위 사이드 패널 접기 버튼 모양을 통일하고, 공문요약·공문서작성기·양식인쇄·수업자료·내 도구 실행 화면의 입력 패널과 학생기록 화면의 학생 목록 패널을 접고 펼칠 수 있게 하였다.

v1.12.1은 예산안 품목의 제목 연관성과 양식 인쇄 활용 폭을 넓히고, 내 스킬 만들기 위저드를 고도화한 릴리즈이다. 예산안작성에서 예산 제목의 주제와 사업 목적을 먼저 분석해 어울리는 품목만 생성하도록 하고, 제목·희망물품에 맞는 품목이 있으면 제목과 무관한 일반 품목(볼펜·복사용지·커피 등)을 후보에서 빼도록 하여 관련 없는 품목이 끼워지는 문제를 개선하였다. 후보 품목 목록은 단가 참고용으로만 사용하도록 명시하였다. 과목별 비율 방식에서도 교육운영비·일반운영비·업무추진비 세 과목 모두에 예산 제목 주제와 연결된 품목이 들어가도록 프롬프트를 보강하였다. HTML 앱 만들기의 어휘 플래시카드 예시는 단어/뜻 쌍 6개(사과/apple 등)가 카드로 미리 채워져 바로 동작하도록 바꾸었다. 양식 인쇄에는 학급 회의록과 1인 1역할 양식을 추가하였으며, 줄 단위로 입력하면 표로 만들어 주는 입력 방식을 새로 도입하였다. 연수 등록부는 참가자 명단을 번호별 입력칸과 '명단 추가' 버튼으로 바꾸어 20명을 넘겨 계속 추가할 수 있게 하고, 명단이 길면 인쇄 시 다음 장으로 이어지도록 하였다. 내 스킬 위저드에는 프롬프트 진단 기능을 추가하였다. 작성한 프롬프트를 AI가 분석해 0~100점의 점수와 한 줄 총평, 심각도별(높음·중간·낮음) 이슈 카드(문제 설명과 구체적 개선 제안 포함)를 보여주며, '개선안 적용' 버튼으로 프롬프트 전체를 한 번에 교체할 수 있다. 프롬프트를 직접 수정하면 이전 진단 결과는 자동으로 사라져 낡은 피드백이 남지 않는다. 위저드는 기존 3단계에서 4단계로 확장되었으며, 4단계에서는 저장 전에 샘플 값을 입력하고 테스트 실행을 눌러 AI 결과를 바로 확인할 수 있다. 이로써 스킬 제작 루프(작성 → 진단 → 수정 → 테스트 → 저장)가 에디터 안에서 완결된다.

v1.12.2는 전체 자료 백업의 누락 데이터를 보완한 릴리즈이다. 기존 백업은 electron-store 설정과 데이터 폴더의 JSON 파일만 저장하여, 렌더러의 localStorage에 보관되던 공문 생성 히스토리(`edunote_generated_document_history_v1_*`), 사이드 메뉴 순서(`edunote_menu_order_*`), 공문서 양식 즐겨찾기(`edunote_doc_template_favorites_v1`), 학생별 생성 히스토리(`eduHist_*`) 등이 백업·복원이나 PC 이전 시 유실되는 문제가 있었다. 이를 해결하기 위해 백업 내보내기 시 렌더러가 localStorage 전체를 키:값 형태로 수집해 백업 payload에 포함하고(schemaVersion 2), 불러오기 시에는 메인 프로세스가 저장된 localStorage 객체를 렌더러로 반환하면 렌더러가 기존 항목을 지운 뒤 복원하고 화면을 자동 새로고침하도록 하였다. localStorage 필드가 없는 이전 형식(schemaVersion 1) 백업도 오류 없이 그대로 불러올 수 있도록 하위 호환을 유지하였다. API 키 등 민감정보는 종전과 동일하게 백업에서 제외된다.

같은 릴리즈에서 AI 생성의 가용성을 높이기 위해 모델 폴백 체인을 도입하였다. 기존에는 무료 `gemini-2.5-flash-lite`, 유료 `gemini-2.5-pro` 단일 모델만 사용하여, 해당 모델이 요청 제한(쿼터)이나 권한 문제로 막히면 모든 AI 기능이 동시에 중단되었다. 이를 개선하기 위해 티어별로 모델 목록(무료: gemini-2.5-flash-lite → gemini-2.0-flash → gemini-2.0-flash-lite, 유료: gemini-2.5-pro → gemini-2.5-flash → gemini-2.0-flash)을 두고, 앞 모델이 쿼터 초과나 접근 불가로 실패하면 다음 모델로 이어서 생성을 시도하도록 하였다. 모델별 차단 상태(쿼터 60초 쿨다운, 권한·미지원 1시간 임시 차단)는 기존 관리 로직을 그대로 재사용한다. 네트워크 오류처럼 모델을 바꿔도 동일하게 실패하는 오류는 종전과 같이 즉시 전파한다.

또한 회귀를 방지하기 위한 자동 테스트 기반을 마련하였다. 그동안 약 19,000줄 규모의 렌더러 코드에 테스트가 전무했는데, vitest와 jsdom을 도입하고(`npm test`로 실행) 부작용 없는 순수 로직부터 단위 테스트로 보호하였다. 1차 대상은 개인정보 보호 모드의 학생 이름 토큰 치환·복원(`withStudentPrivacy`), 학생 메모 포맷팅(`formatStudentMemos`), 가져온 스킬 JSON 검증(`validateImportedTool`·`parseImportedTools`), HTTPS URL 검사(`isSafeHttpsUrl`), 생성 결과 HTML 정화(`sanitizeHtml`)와 마크다운·HTML 변환(`markdownOrHtmlToHtml`)이며, 정상·경계·악성 입력 케이스를 포함해 총 36개 테스트를 작성하였다. DOM API(DOMParser)를 사용하는 정화 로직은 jsdom 환경에서 검증한다. 예산안 계산 로직 등은 현재 거대 컴포넌트에 인라인되어 있어, 별도 모듈로 추출하는 작업과 함께 후속 테스트 대상으로 둔다.

마지막으로 접근성을 보완하였다. 재사용 훅 `useEscapeKey`를 추가하여 닫기 동작이 있는 모달(API 키 안내, 학교급 선택)을 Esc 키로 닫을 수 있게 하였다(동의 체크가 필요한 면책 모달은 닫기 동작이 없어 제외). 세 모달 컨테이너에는 `role="dialog"`·`aria-modal="true"`·`aria-labelledby`를 부여해 제목과 연결하고, 헤더·사이드바의 아이콘 전용 버튼(다크모드 전환, 메뉴 접기·펼치기, 홈)에 `aria-label`을 추가해 스크린리더 사용성을 높였다. 모든 아이콘 버튼을 일괄 변경하지 않고 사용 빈도가 높은 상단·사이드 영역부터 적용하는 패턴으로 진행하였다.

v1.13.0은 UI 리뉴얼을 시작으로 온보딩, 메뉴 구조, 개인정보 안내, 문서 출력 기준을 함께 정리한 릴리즈이다. 기존 앱은 차가운 회색 계열(`gray`/`slate`) 팔레트와 시스템 기본 글꼴을 사용했는데, 이를 베이지·차콜 톤의 따뜻한 팔레트(라이트 모드 `#FAF9F7`/`#FFFDF9`/`#FFFFFF`, 다크 모드 `#171210`/`#1D1916`/`#221E1B` 계열)와 Pretendard 글꼴로 교체하였다. 적용 범위는 앱 셸(사이드바·헤더·모달·토스트), 홈·설정·사용법·About·시연 샘플 등 공용 화면, 교무행정·수업자료·학생기록·AI스킬즈 4개 영역의 전체 화면이며, 영역별 강조색(교무행정=에메랄드, 수업자료=앰버, 학생기록=인디고, AI스킬즈=핑크)과 위험·정보·성공 등 의미 전달용 기능색은 기존 그대로 유지하였다.

온보딩은 사용동의, API 키 입력, 사용자설정 입력의 3단계로 정리하였다. 앱을 시작할 때 사용 동의 화면이 먼저 표시되며, 기존에 저장된 이름·소속기관·학교급·담당 학년/반과 API 키 상태는 그대로 반영된다. 사용자는 동의 체크 후 다음 단계로 진행하거나 바로 창을 닫고 앱을 사용할 수 있다. 저장된 API 키는 보안상 원문을 다시 표시하지 않고, 저장된 키가 있다는 안내만 보여준다.

메뉴 구조는 사이드바의 중복 하위 메뉴를 줄이고 상단 탭 중심으로 정리하였다. 공문서 9종, 학생기록 세부 메뉴, 우리반기록, 수업 도구, 내 스킬/스킬마켓은 각 화면 상단에서 가로 탭으로 선택한다. 다른 메뉴로 이동해도 생성 중인 작업 진행률이 상단 탭 또는 접힌 사이드바 아이콘에 표시되도록 하였다. 메인 사이드바를 접어도 홈, 설정, 교무행정AI, 공문요약, 공문서 작성기, 수업자료AI, 학생기록AI, AI 스킬즈, 사용 방법, 도움말 / 정보 아이콘이 남아 바로 이동할 수 있다.

상단 레이아웃도 추가로 정리하였다. 본문 상단 강조선이 화면 높이를 밀어내지 않도록 오버레이로 처리하고, 사이드바 제목 바와 본문 상단 탭·각 기능 첫 헤더를 같은 높이 기준으로 맞추었다. 홈 화면의 마지막 백업 시간과 `자료 백업하기` 버튼은 좁은 창에서도 겹치지 않도록 날짜 영역을 말줄임 처리하고 버튼 폭을 고정하였다.

문서 생성 품질도 보강하였다. 학생기록 계열에서는 학생 이름이 본문에 반복적으로 들어가지 않도록 결과 후처리를 강화하고, 행동발달·교과 세특·스포츠클럽·창체 문장의 종결을 생활기록부 문체에 맞게 `노력함.`, `성장함.`처럼 정리하였다. 공문서 작성기는 예시 문서 형식을 더 강하게 따르도록 하고, 모든 공문서 출력물을 A4 기준으로 배치하며 내용이 길면 문장·표·항목이 중간에 잘리지 않는 지점에서 다음 장으로 넘기도록 지침을 추가하였다. 수업자료는 특별한 요청이 없으면 A4 한 장 기준으로 구성하고, 퀴즈·활동지·수업계획서 인쇄 시 문항·표·활동 단위가 잘리지 않도록 출력 CSS를 보강하였다.

개인정보 안내와 백업 흐름도 명확히 하였다. 도움말 / 정보와 사용 방법 화면에 앱 자료가 사용자 컴퓨터에 저장된다는 점, Gemini API 키는 백업 파일에 포함하지 않는다는 점, AI 기능 사용 시 민감정보 입력을 피해야 한다는 점을 안내하였다. 홈 화면의 마지막 백업 카드 옆에는 `자료 백업하기` 버튼을 추가해 설정 화면으로 이동하지 않고도 백업할 수 있게 하였다. 공문요약·업무추출의 Google Calendar 추가는 일반 일정 날짜보다 마감·기한·제출·신청·접수·회신 문맥의 날짜를 우선 사용하도록 개선하였다.

시연 자료도 현재 기능 흐름에 맞게 보강하였다. Demo 창과 `DEMO_SAMPLES.md`의 공문요약·업무추출 샘플에 참고 웹사이트 주소를 추가하여 일정·마감일·URL이 포함된 공문을 한 번에 시연할 수 있도록 하였다.

v1.13.1은 v1.13.0에서 강화했던 생성 프롬프트 기준을 실제 사용자가 선호하던 v1.12.1 흐름으로 되돌린 패치 릴리즈이다. 문서작성기(구 공문서 작성기), 수업자료 AI, 생기부도우미의 결과물 작성 프롬프트에서 v1.13.0에 추가된 학생기록 종결어미 강제 후처리, 공문서 A4 페이지 분할 지시, 수업자료 인쇄 분할 보강 지시를 제거하였다. 이로써 화면 리뉴얼과 온보딩, 메뉴 구조 개선은 유지하면서도 생성 결과의 문체와 구조는 v1.12.1에 가까운 기준으로 복원하였다.

이어서 '공문서 작성기' 메뉴명을 '문서작성기'로 변경하여 사이드바·접힌 사이드바 아이콘·사용 방법 화면·데모 샘플 전반에 통일했다. 또한 상세 공문 작성 시 항상 표가 포함되던 것을, 세부추진계획처럼 일정·역할 분담 등 줄 단위로 비교·정리해야 하는 내용이 있을 때만 그 부분에 한해 표를 사용하도록 프롬프트 지침을 다듬어 불필요한 표 생성을 줄였다.

같은 릴리즈에서 내 스킬 만들기의 프롬프트 진단 기능을 제거하였다. 작성한 프롬프트를 점수와 이슈 목록으로 평가하는 방식 대신, 사용자가 `AI 도움받기`를 누르면 현재 작성된 프롬프트를 AI가 직접 다듬어 주는 흐름으로 단순화하였다. 프롬프트 개선 지시에는 도구 설명, 입력 변수, 기존 프롬프트를 함께 보고 실제 의도와 결과물 장르를 먼저 파악하라는 조건을 추가하였다. 일기 분석, 감상문 피드백, 상담 기록, 문서 요약, 공문서 작성, 수업자료 제작, 학생 기록 작성 등 서로 다른 작업을 혼동하지 않도록 하고, 예를 들어 일기 분석 도구를 공문서 형식으로 바꾸는 식의 장르 전환을 금지하였다.

v1.13.2는 기능 추가 없이 전체 코드 리뷰 결과를 반영한 보안·안정성·사용성 보완 릴리즈이다. 보안 측면에서는 폴더 열기 경로 검증을 실제로 동작하도록 고치고, AI 생성 IPC 요청의 형식·크기를 메인 프로세스에서 한 번 더 검증하며, 생성 결과 버전 기록 HTML을 화면 표시 직전에 다시 소독해 저장된 기록 변조에 의한 스크립트 실행을 막았다. 설정 저장과 백업 복원에는 항목별 형식 검증을 추가하고, HTML 미리보기·PDF 변환용 임시 파일을 매 실행마다 새로 만드는 임시 폴더에 두고 종료 시 정리하도록 했다. 가격 조회(나라장터·인터넷 가격조회) 자격증명은 화면에서 주고받지 않고 앱 저장소에서만 읽도록 바꿔 저장된 Client Secret이 화면에 다시 노출되지 않게 했고, 인터넷 조회 기능에는 내부 주소(localhost 등) 접근을 막는 SSRF 가드를 적용했다. 메인 창과 데모 창에 렌더러 샌드박스를 적용하고 내장 브라우저(webview)의 보안 정책을 강화했다. 안정성 측면에서는 localStorage 저장 실패를 안전하게 처리하고, AI 응답 JSON 파싱을 공용 유틸로 안전화했으며, 생성 실패 원인(API 키 없음·키 오류·사용량 초과·시간 초과·네트워크 오류)을 구분해 안내하도록 했다. 생성 중단 신호를 화면 단위로 분리해 한 화면의 중단이 다른 화면 생성을 끊던 문제와 중단 직후 뒤늦은 결과 반영 문제를 함께 고쳤다. 개발 편의를 위해 타입 검사 스크립트를 추가하고 기존 타입 오류를 정리했다. 사용성 측면에서는 설정·사용 방법 화면의 다크 모드 색상 누락을 고치고, 화면 곳곳의 시스템 알림창(alert)을 작업 흐름을 막지 않는 토스트 알림으로 전환했다. 이 과정에서 삭제 확인 대화상자와 생성 진행률·중단 버튼, 주요 내비게이션 버튼의 접근성 라벨은 이미 구현되어 있음을 확인하였다. 또한 Google AI Studio에서 API 키 발급이 거부되며 "Google Cloud에서 만들기" 안내가 나오는 경우에 대비해, 원인별 대응(학교 계정이면 개인 Gmail 계정으로 재시도, Cloud Console에서 새 프로젝트·Generative Language API 사용 설정·사용자 인증 정보로 직접 발급, 결제 요구 시 유료 등급 주의)을 설정 화면 발급 가이드·온보딩·사용 방법 화면·사용자매뉴얼(17.5절)에 추가하였다.

같은 릴리즈에서 이전에 도입했다가 동작 문제로 제거했던 AI 생성 모델 자동 전환을 다른 방식으로 재도입하였다. 과거 방식은 모델 이름을 하드코딩으로 추측해 사용자 키에서 제공되지 않는 모델로 요청을 낭비했고, 분당 제한과 일일 한도를 구분하지 않아 무료 키 환경에서 효과가 없었다. 새 방식은 API 키로 실제 사용 가능한 모델 목록을 조회(세션당 1회 캐시)해 선호 순서와의 교집합만 폴백 후보로 쓰고, 분당 제한(429)이면 응답에 포함된 재시도 대기 시간(retryDelay)만큼 기다린 뒤 같은 모델로 한 번 더 시도해 문체 일관성을 유지하며, 일일 한도 소진이면 해당 모델을 10분간 차단하고 다음 모델로 폴백한다. 모든 시도가 막히면 분당 제한과 일일 한도를 구분한 안내를 표시하고, 모델 목록 조회에 실패하면 기존처럼 기본 모델 1개로만 동작해 어떤 경우에도 종전보다 나빠지지 않도록 했다.

이어서 생성 프롬프트와 호출 메커니즘을 전반적으로 보완하였다. 메커니즘 측면에서는 무료 키의 분당 15회 제한에 맞춰 AI 호출 간 최소 4초 간격을 자동 적용하고(일괄 생성 중 429 연쇄 방지), 텍스트형 생성에 출력 토큰 상한을 두었으며, JSON을 기대하는 기능(예산안 품목, 퀴즈, 슬라이드, NEIS 분석, 대화형 스킬 생성)에 Gemini JSON 응답 모드를 적용해 파싱 실패를 줄였다. 챗봇은 대화 기록을 최근 6개만 전송하고 시스템 안내문을 경량화했다. 프롬프트 측면에서는 학생기록 결과의 기재요령 주의 표현(교외 대회·수상, 공인어학시험, 특정 대학명, 논문·특허, 어학연수)을 자동 감지해 토스트로 경고하는 안전망을 추가하고, 세특의 작성 흐름 기준을 5단계로 통일하면서 성취수준별 표현 기준을 명시했으며, 창체는 활동 영역별(자율/동아리/진로/봉사) 기재 기준을 분리했다. 일괄 생성 시 학생마다 서술 시작 관점을 순환시켜 결과 반복성을 완화하고, 문서작성기에는 입력에 없는 법령·공문번호 추측을 금지하는 지시와 회의록 고정 표 템플릿을 추가했다. 배치 생성 진행률은 기존부터 실제 학생 수 기반으로 표시되고 있음을 확인하였다. 추가로 문서작성기에 스트리밍 생성을 도입해 생성 중인 내용을 실시간 미리보기로 보여주고(모델 폴백·재시도 시 미리보기 자동 초기화), 워크시트는 생성 직후 숨김 프레임에서 렌더 높이를 측정해 A4 한 장 초과가 추정되면 안내하며, 텍스트류 첨부 파일(txt·md·csv)은 base64 대신 텍스트로 변환해 전송하고 3만 자 초과분은 절단하도록 했다.

v1.13.3은 한글(HWP)에서 "사용할 수 없는 파일"로 표시되어 비활성화해 두었던 HWPX 저장을 복구한 패치이다. 실제 한글이 생성한 빈 문서와 출력물을 바이트 수준에서 비교해 원인을 특정했다. 양식 채우기 경로는 JSZip이 재생성 과정에서 원본에 없던 폴더 항목(Contents/)을 추가해 압축 파일 구조가 정상 파일과 달라지는 문제가 있었고, 내장 생성 경로는 version.xml·header.xml 등 필수 구성요소가 빠진 임의 구조의 파일을 만들고 있었다. 양식 채우기는 원본 항목을 순서 그대로 새 zip에 복사하고 수정된 본문만 교체하는 명시적 재포장으로 바꾸고, 내장 생성은 한글이 실제로 여는 검증된 빈 문서(Apache-2.0 공개 픽스처)를 골격으로 내장해 골격 문단과 같은 스타일 ID로 본문 문단을 주입하는 방식으로 재작성했다. 출력 파일의 항목 구성·순서·압축 방식이 정상 한글 파일과 동일함을 단위 테스트로 검증하며, 최종 확인은 실제 한글에서 파일을 여는 사용자 검증으로 완료한다. 생성 결과 화면의 저장 형식 목록에도 HWPX를 추가해 양식 업로드 없이 .hwpx로 바로 저장할 수 있게 했다.

같은 버전에서 문서 생성이 영원히 끝나지 않던 문제도 수정했다. 모델이 글자 없는 빈 문단 마크업만 끝없이 반복 출력하는 경우 API 오류가 발생하지 않아 모델 폴백이 동작하지 않았고, 스트리밍 소비 루프에 시간 제한도 없었다. 누적 출력의 꼬리 3,000자에서 태그·공백을 걷어냈을 때 보이는 글자가 거의 없으면 비정상 반복으로 판단해 스트림을 닫고 다음 모델로 폴백하는 감지 로직(streamGuard)을 추가했으며, 청크 간 45초 무응답 시에도 같은 방식으로 폴백한다. 감지 로직은 SDK 의존 없는 순수 모듈로 분리해 단위 테스트(빈 마크업 반복 감지, 표 등 마크업 많은 정상 문서 통과, 태그 경계 절단 처리)로 검증했다.

문서작성기의 입력 부담도 줄였다. 기존에는 빈 입력칸이 빈 값 그대로 프롬프트에 들어가 결과 품질이 들쭉날쭉했는데, 이제 빈 칸은 "(미입력)"으로 표기해 전송하고, 미입력 항목은 제목·주제와 문서 맥락에 어울리는 내용으로 추정해 채우되 결과물에 "(미입력)"류 표시를 남기지 말라는 전역 지침을 함께 보낸다. 일시·기간은 학년도와 오늘 날짜를 참고해 제안하도록 했다. 다만 근거 법령·공문번호·통계는 기존 근거·출처 작성 규칙(추측 금지, 사용자가 채울 자리로 표시)이 우선하도록 명시해, 편의성 개선이 잘못된 근거 생성으로 이어지지 않게 했다.

AI스킬즈의 대화로 만들기는 결과물 유형 선택 단계를 추가해 고도화했다. AI 스킬·HTML 앱·둘 다 중에서 고르면 유형에 맞춰 질문이 분기되고(앱은 기능·화면과 디자인을 묻고 양식 첨부 단계를 생략), 둘 다 선택 시 한 번의 대화로 스킬과 앱이 함께 생성된다. 앱은 목록에 바로 저장되고(이름 뒤 "(앱)" 표시) 스킬은 기존처럼 위저드 확인을 거친다. 설계 품질도 보강했다. 기존 설계 프롬프트는 입력 필드를 만들면서도 지시문에 자리표시자를 넣으라는 규칙이 없어, 실행 시 입력값이 AI에게 전달되지 않는 스킬이 만들어질 수 있었다. 이제 모든 입력 필드를 {{field_n}} 형태로 지시문에 반드시 참조하고, 역할·작업·출력 형식을 충실히 담으며, 필드 유형(text/textarea/file-upload)과 필수 여부까지 설계하도록 규칙을 명시했다. 둘 다/앱 모드에서는 같은 설계 호출에서 앱 구현 요구사항(appSpec)을 함께 받아 HTML 앱 생성에 사용한다. 앱 생성만 실패한 경우에는 스킬이라도 저장하도록 처리했다.

v1.13.4는 v1.13.3 이후에도 생성 결과의 HWPX 저장 파일이 한글에서 열리지 않는다는 사용자 보고를 받아, 한글 11이 직접 저장한 정상 .hwpx 파일(문단 2,685개·표 82개)과 출력물을 zip·XML 수준에서 1:1 대조해 원인을 특정한 패치이다. 결함은 세 가지였다. 첫째, 재포장 시 모든 항목을 압축해 첫 항목 mimetype까지 압축되었는데, HWPX가 따르는 OCF 컨테이너 규격은 mimetype을 첫 항목·무압축으로 요구하며 한글 원본 파일도 mimetype·version.xml을 무압축으로 저장한다. 둘째, 주입한 모든 문단에 줄 배치 정보(linesegarray)가 없었는데 한글 원본은 사실상 모든 문단에 이를 포함한다. 셋째, 표를 텍스트로 변환하며 넣은 탭 제어문자가 텍스트 안에 그대로 남았는데 한글 원본은 탭을 hp:tab 요소로 표현한다. 세 가지를 모두 한글 원본과 동일한 방식으로 수정하고, XML에서 허용되지 않는 제어문자 제거도 추가했다. 나아가 HTML→OWPML 변환기를 새로 구현해 HWPX 저장 시 서식이 유지되도록 했다. 문서 제목은 22pt 굵게·가운데 정렬, 절 제목은 14pt 굵게, 문단의 가운데·오른쪽 정렬과 굵은 글씨(run 분리), 목록 표식이 반영되고, 표는 한글 원본 파일에서 실측한 hp:tbl 구조 템플릿(테두리 borderFill, 머리글 행 굵게·가운데, colspan/rowspan 셀 병합, 그리드 좌표 계산)으로 진짜 한글 표로 저장된다. 필요한 글자·문단·테두리 속성은 골격 header.xml의 기존 항목을 복제·변형해 런타임에 주입하며(itemCnt 갱신 포함), 문서 구조를 해석할 수 없는 예외 상황에서는 평문 폴백으로 저장해 어떤 경우에도 파일이 열리도록 했다. OCF 시그니처(무압축 mimetype 평문 위치), 문단-linesegarray 수 일치, 탭 변환, 스타일 ID 정합성, 표 구조, header 주입을 단위 테스트 11건으로 검증했고, 최종 확인은 사용자가 실제 한글에서 여는 것으로 완료한다.

v1.14.0은 HWPX 저장 품질을 마무리하고 학교 현장 요청 기능 4종을 더한 버전이다. 한글에서 긴 문단의 글자가 겹쳐 보이던 문제는 모든 문단에 lineseg를 한 개만 부착해 여러 줄 문단의 각 줄이 같은 자리에 그려진 것이 원인이었다. 전각·반각 글자 폭으로 문단의 줄 수를 추정해 줄마다 textpos·vertpos가 증가하는 lineseg를 생성하도록 고쳤고(정확한 줄바꿈은 한글이 편집 시 재계산), 표 셀 안 문단은 셀 폭 기준으로 추정한다. 저장 기본 포맷도 사용자 요구대로 확정했다: 제목 22pt 굵게·가운데, 기관명·본문·표 안 내용 14pt, "1." 수준 15pt, "가."/"1)"/"(1)"/"①" 수준은 단계마다 두 칸씩 들여쓰기(줄머리 기호 정규식으로 수준 감지). 파일명용 제목이 본문 맨 위에 "생성문서" 같은 가짜 제목 문단으로 들어가던 동작을 제거해 미리보기에 보이는 내용만 저장되게 했고, HWPX 파일명에도 (YYMMDD)_제목 형식으로 날짜를 붙였다. 신규 기능으로는 ① 자동 정기 백업(설정 주기 경과 시 앱 시작 때 데이터 폴더 backups에 무대화상자 저장, 최근 10개 보관, 수동 백업과 페이로드 공용) ② 공문 할일 목록(공문요약·업무추출의 '할일로 저장'으로 제목·마감일 자동 추출 적재, D-day 배지와 마감일 정렬, 앱 시작 시 마감 3일 이내 알림, doc-todos.json 저장으로 백업 자동 포함) ③ 가정통신문·메시지 다국어 번역(미리보기 툴바에서 13개 언어 선택 — 러시아어·우즈베크어 포함, 번역문을 원문 아래 병기해 그대로 인쇄·배포, 이름·날짜·연락처 비번역 규칙, 원문 복원) ④ 간단 번역 도구(교무행정AI 메뉴, 한국어↔외국어 양방향 좌우 비교 화면)를 추가했다. 번역 언어 목록과 프롬프트는 공용 모듈(lib/translation.ts)로 분리해 세 기능이 공유한다.

v1.14.0 이후에는 사용성 보완 세 가지를 진행했다. 첫째, 가정통신문 등 표가 포함된 문서를 번역할 때 한글보다 긴 외국어 단어가 표 칸을 늘려 미리보기 화면 밖으로 표가 넘치던 문제를, 표에 고정 레이아웃(table-layout:fixed)과 셀 단어 줄바꿈(word-break/overflow-wrap)을 적용하고 번역 결과를 화면에 주입한 직후에도 같은 서식을 다시 적용하는 방식으로 고쳤다(공용 헬퍼 applyDocumentStyles로 추출해 초기 렌더와 번역 후 모두 호출). 동일 서식을 PDF·Word·HWPX 내보내기 경로에도 반영했다. 둘째, 시연용 Demo 화면의 각 샘플에 기능 한 줄 설명·사용 순서·기대 결과 필드(desc·steps·result)를 추가하고, 문서작성기 샘플 명칭을 실제 탭 이름(회의록·홍보자료)과 일치시켜 처음 보는 사용자도 기능을 이해하기 쉽게 보강했다. 셋째, 화면 위에서 실제 요소를 단계별로 하이라이트하며 안내하는 인터랙티브 튜토리얼(실시간 오버레이, 따라 하기 방식)을 도입했다. 외부 라이브러리 없이 자체 오버레이(TourOverlay)와 투어 컨텍스트(TourContext)로 구현했으며, 문서작성기·수업자료 생성·예산안작성 세 화면에 파일럿으로 적용했다. 각 화면의 `튜토리얼` 버튼으로 시작하고, 투어 정의(lib/tours.ts)에 항목을 더하고 대상 요소에 data-tour 속성만 달면 다른 메뉴로 확장되도록 설계했다.

v1.15.6은 기능 추가 없이 전체 코드 리뷰 결과를 반영한 보안·안정성·사용성 보완 릴리즈이다. 보안 측면에서는 저장 폴더 자동 저장 경로에서 렌더러가 넘긴 파일명의 경로 구분자·예약 문자를 제거하고 저장 폴더 내부인지 검증해 폴더 밖 임의 위치 쓰기를 차단하고(위반 시 저장 대화상자로 폴백), 이를 순수 함수(resolveAutoSavePath)로 분리해 단위 테스트로 검증했다. 앱 본 창(webview 게스트 제외)이 외부 오리진으로 이동하는 것을 will-navigate에서 막아 preload 재주입에 의한 electronAPI 노출을 방지하고 http(s) 주소는 기본 브라우저로 넘기도록 했으며, PDF 변환용 임시 창에도 렌더러 샌드박스를 적용해 다른 창과 격리 수준을 맞췄다. 안정성 측면에서는 학생기록·챗봇 등 AI 생성 함수가 실패 시 오류 문구를 정상 결과 문자열로 반환하던 계약 불일치를 예외 처리로 통일해, 오류 문구가 생성 히스토리에 저장되거나 중복 문장 검사·지침 위반 검사 대상이 되던 문제를 없앴다(챗봇 화면은 구체적 오류 메시지를 그대로 안내). 업데이트 확인의 버전 비교를 접미사(-beta 등)가 붙은 태그에서도 숫자 부분으로 안전하게 비교하도록 고쳐 별도 모듈·테스트로 분리했고, 슬라이드 이미지 생성이 무료 키만 참조하던 것을 활성 티어 키 기준으로 바꾸었다. 외부 URL JSON 요청은 리다이렉트마다 연결 타임아웃이 초기화되던 문제를 전체 단일 마감 시각 방식으로 바꾸고, 종료 경로와 무관하게 타이머·리스너를 정리하도록 했다. 학생별 생성 히스토리(eduHist_*) 키가 학생 수 누적으로 무한정 늘어나던 문제를 총 키 상한(300개) 초과 시 오래된 키부터 정리하도록 보완하고 테스트를 추가했다. API 키 검증 함수에 남아 있던 미사용 다중 모델 순회 로직을 단일 모델 검증으로 정리(동작 동일)했다. 사용성 측면에서는 채팅 입력창의 한글 IME 조합 중 Enter 조기 전송을 isComposing 가드로 막고, 생성기의 학생 상태 직접 변이를 불변 업데이트로 교체했으며, HTML 앱 미리보기의 iframe 리마운트 판정을 길이 대신 내용 해시로 바꿔 이전 앱 상태 잔존을 없앴다. 마크다운/HTML 판별을 마크다운 우선으로 재정렬해 인라인 태그(<br> 등)가 섞인 마크다운이 그대로 노출되던 오판을 고치고 테스트를 추가했으며, 업로드 파일에 15MB 크기 상한을 두었다. 전역 상태 컨텍스트 value를 메모이제이션해 생성 진행(600ms 간격) 중 전체 소비자가 반복 리렌더되던 부담을 줄였다. 총 테스트는 143건에서 157건으로 늘었다.

v1.16.0은 전체 코드 최종 점검을 반영하고 로드맵에 남아 있던 마무리 항목 두 가지를 구현한 정리 릴리즈이다. 첫째, Gemini API 키를 OS 안전 저장소(safeStorage) 암호화 보관으로 이관했다. 암호화 가능 환경에서는 암호문만 저장하고 평문을 남기지 않으며, 앱 시작 시 기존 평문 키를 1회 자동 이관한다. 미지원 환경은 기존 평문 방식으로 폴백하고, 설정 파일을 다른 PC로 복사해 복호화가 불가능한 경우는 키 없음으로 처리해 재입력을 유도한다. 로직은 electron에 직접 의존하지 않는 주입식 모듈로 분리해 단위 테스트로 검증했다. 둘째, 다크 모드 미적용으로 남아 있던 교무행정AI 챗봇·상담일지·수업관찰기록 세 화면에 표준 다크 팔레트를 이식해 앱 전 화면의 다크 모드 지원을 완성했다. 보안 측면에서는 netGuard가 16진 그룹 형식의 IPv4 매핑 IPv6 주소(::ffff:7f00:1)를 걸러내지 못해 루프백 차단이 우회되던 빈틈을 실제 재현 후 차단했고, 본 창 외부 이동 검사의 프로토콜 비교를 정확 일치로 고쳤으며, HTML 번역 결과에 새니타이즈를 적용했다. 안정성 측면에서는 1.15.6에서 누락됐던 창의적 체험활동 생성기의 상태 직접 변이 7곳을 불변 업데이트로 교체했다. 정리 측면에서는 미사용 화면 컴포넌트 2종과 고아 코드를 삭제하고, 릴리즈 워크플로에 타입체크·테스트 품질 게이트를 추가해 테스트를 통과한 코드만 배포되도록 했다. 총 테스트는 157건에서 169건으로 늘었다.

v1.18.1은 무료 등급 모델 세대를 갱신한 릴리즈이다. 기존 FREE_MODEL_PREFERENCE는 gemini-2.5-flash-lite를 최우선으로 두고 있었는데, 조사 결과 구글이 이미 Gemini 3세대(3.1 Flash-Lite 등)로 넘어갔고 무료 티어에서도 사용 가능함을 확인해 gemini-3.1-flash-lite를 목록 맨 앞에 추가했다. buildModelChain이 키로 실제 조회한 모델 목록과 선호 순서의 교집합만 사용하는 기존 구조를 그대로 활용했기 때문에, 새 모델을 추가만 하고 기존 2.5·2.0 계열 항목은 전혀 건드리지 않았다 — 키가 연결된 프로젝트에 아직 3세대 모델이 열리지 않았거나 목록 조회 자체가 실패해도 기존과 동일하게 동작한다(폴백 안전성 유지). 모델 ID 문자열은 구글 공식 문서(ai.google.dev) 직접 접근이 차단되어 있어 여러 매체 교차 확인으로 파악했으며, 사용자가 로컬에서 직접 실행할 수 있는 진단 스크립트(scripts 폴더 미포함, 저장소 밖에서 실행)로 실제 키 기준 동작 여부를 확인하도록 안내했다.

v1.18.2는 v1.18.1에 이어 생기부 도우미 결과에 실제 생성 모델을 노출한 릴리즈이다. 모델 폴백 체인 도입 이후 어떤 모델이 실제로 응답을 만들었는지 사용자가 알 방법이 없었는데, 회귀 위험을 낮추는 것을 최우선으로 설계했다. 메인 프로세스의 generateContent·generateContentMultipart·generateContentMultipartStream이 텍스트만 반환하던 것을 {text, model} 형태로 바꾸고 IPC 타입(ElectronAPI 인터페이스)도 함께 갱신했지만, 렌더러의 저수준 aiGenerate·aiGenerateMultipart·aiGenerateMultipartStream 함수에는 선택적 onModel 콜백만 추가해 기존 반환 타입(Promise\<string\>)을 그대로 유지했다. 그 결과 이 파일 안의 생성 함수 46개 중 생기부 도우미 4개(generateOpinion·generateSubjectReport·generateSportsClubReport·generateCreativeActivityReport)만 반환 타입을 {text, model}로 바꾸고, 나머지 42개와 그 호출부는 한 줄도 바뀌지 않았다. 타입을 변경한 지점에서 TypeScript 컴파일러가 고쳐야 할 자리를 전부 오류로 잡아주므로 수동 검색으로 놓치는 위험을 줄였고, 실제로 컴파일러가 지목한 곳(BudgetPlannerScreen·MyResourceLibrary·translation.ts처럼 window.electronAPI.aiGenerate를 직접 호출하던 3개 파일 포함) 외에는 손대지 않았다. 4개 학생 데이터 인터페이스(StudentOpinionData 등)에 generatedModel 필드를 추가하고, 결과 화면 학생 이름 옆에 실제 사용된 모델명을 작은 태그로 표시했다. 다만 이 세션에는 유효한 Gemini API 키가 없어 실제 생성 성공 경로(뱃지가 채워지는 순간)까지는 확인하지 못했고, 타입체크·테스트 통과와 화면 정상 로드까지만 검증했다.

v1.18.3은 v1.18.2의 모델 표시 범위를 생기부 도우미 밖으로 넓힌 릴리즈이다. 같은 onModel 콜백 패턴을 문서작성기(generateDocument — 공문서·계획서·보고서·품의서·회의록·홍보자료·가정통신문·메세지·공고문 9종을 한 함수가 처리), 상담일지·학급경영일지·수업관찰기록(교사 업무 기록 3종, 개인정보 보호 래퍼 안쪽에 콜백 추가), 공문요약(analyzeOfficialDocument — 파일 첨부 유무에 따라 두 경로 모두 처리), 수업자료 4종(워크시트·퀴즈·수업계획서는 {text, model}, 슬라이드는 배열을 반환하므로 {slides, model}로 별도 처리), AI스킬즈(runCustomTool은 파일 배치 처리·병합 호출까지 있어 마지막으로 성공한 모델을 usedModel에 계속 덮어쓰는 방식으로 단순화, generateHtmlApp)까지 총 11개 함수에 적용해 8개 컴포넌트에 배지를 노출했다. 문서작성기·수업자료 워크시트/계획서·AI스킬즈 테스트/실행 화면은 이미 결과를 보여주던 공용 컴포넌트 GeneratedDisplay를 그대로 재사용할 수 있어, 이 컴포넌트에 `model?: string` prop 하나만 추가해 여러 화면이 동일한 배지 UI를 공유하도록 했다. 반대로 이번 범위에서 제외한 함수도 있다: parseAssessmentTasks·parseNeisGradeFiles·parseStudentObservationFromFiles·parseAnnualPlanFromImages/Documents는 파일에서 추출한 값을 입력 폼에 채우는 중간 단계이지 사용자가 저장·인쇄하는 최종 "결과물"이 아니고, generateToolFromChat·generateToolPrompt는 스킬 제작 마법사 내부에서 쓰는 초안·진단 텍스트이며, generateLessonGame은 UI에서 더 이상 호출되지 않는 죽은 코드(게임 제작 메뉴가 v1.8.0에서 제거됨)이고, askRecordChatbot·askEducationQuestion은 대화형 챗봇이라 결과 카드 하나가 아닌 메시지 버블 목록 구조라 같은 패턴을 그대로 적용하기 어렵다. 모델 배지는 GeneratedDisplay의 헤더에만 렌더링되고 content(복사·저장·인쇄에 쓰이는 실제 텍스트)와는 분리되어 있어, 화면에는 보이되 저장·인쇄되는 결과물에는 섞이지 않는다.

v1.18.4는 사용자가 실제로 겪은 두 가지 증상 — 계획서·보고서의 "1. 2. 3." 개조식 항목이 한 줄로 뭉쳐 보이는 것과, 워크시트 미리보기에 `<table>` 같은 HTML 태그가 글자 그대로 노출되거나 화면이 통째로 비어 보이는 것 — 을 하나의 근본 원인으로 좁혀 고친 릴리즈이다. 두 화면 모두 AI가 `<!DOCTYPE html>`로 시작하는 완성된 HTML 문서를 만드는데, `markdownOrHtmlToHtml`(src/renderer/lib/generatedContent.ts)의 HTML 시작 판별 정규식이 `/^<[a-z][\s\S]*>/i`여서 `<!DOCTYPE`의 두 번째 글자 `!`가 `[a-z]`에 걸리지 않아 판별을 통과하지 못했다. 그 결과 완성된 HTML 문서가 아래의 마크다운 판별 단계로 새어 나갔고, 계획서·워크시트 본문에 흔히 들어가는 "1. 문제" 같은 번호 목록 텍스트가 `/^\d+\.\s/m` 패턴에 걸려 마크다운으로 오판되었다. remark는 기본 설정(`allowDangerousHtml` 미지정)에서 원시 HTML 블록을 렌더링 결과에서 통째로 제거하므로, 문서 전체가 빈 줄 없이 이어져 있으면 화면이 완전히 비고, 중간에 빈 줄이 있어 일부만 원시 HTML 블록으로 인식되면 나머지가 개별 문단으로 쪼개지며 HTML 태그가 글자 그대로 이스케이프되어 노출되었다. 실제로 remark 파이프라인에 이런 문서를 통과시켜 결과가 완전히 빈 문자열로 나오는 것을 직접 재현해 원인을 확정했다. 수정은 두 가지다. 첫째, `markdownOrHtmlToHtml`의 HTML 판별 조건에 `/^<!DOCTYPE\s+html/i`를 추가해 이런 문서가 마크다운 판별 단계로 새지 않고 곧바로 HTML로 처리되게 했다. 둘째, `sanitizeHtml`(src/renderer/lib/security.ts)도 함께 손봤다 — 기존에는 모든 입력을 `<div>`로 감싸 파싱했는데, `<!DOCTYPE html>`이나 `<html>`이 포함된 전체 문서를 이렇게 감싸면 브라우저가 중첩된 `<head>`·`<body>` 태그를 일반 자식 요소로 넣지 않고 특수 처리해 `<title>`이 낱개 요소로 새어 나오는 등 구조가 흐트러졌다. 이제 `<html>` 포함 여부를 감지해 그런 문서는 감싸지 않고 그대로 파싱한 뒤 `<head>`의 `<style>`과 `<body>` 내용만 추출해 이어붙인다. 두 수정 모두 jsdom 단위 테스트(회귀 테스트 3건 추가)와 실제 Electron/Chromium 환경 양쪽에서 동일한 동작을 확인했다.

같은 v1.18.4 릴리즈 안에서, 위 수정 이후에도 사용자가 실제 생성한 계획서에서 가./나./다. 항목이 여전히 한 줄로 붙어 보이는 사례가 보고되어 원인을 추가로 좁혔다. `<!DOCTYPE html>` 오판 문제와는 별개로, 문서작성기(SchoolDocPanel)의 계획서·보고서 프롬프트는 애초에 전체 문서를 `<!DOCTYPE html>`로 감싸지 않고 `<div>`/`<h1>` 등 body 조각만 출력하도록 지시하고 있어 앞선 수정의 영향을 받지 않는 경로였다. HWPX 저장 함수(`HwpxGenerator.ts`)가 `<br>` 태그뿐 아니라 원문에 남아 있는 실제 줄바꿈 문자(\n)까지 그대로 문단 구분에 사용하고 있었던 반면, 화면 미리보기는 일반 HTML 흐름(white-space 기본값)에서 줄바꿈을 한 칸으로 접어버리는 차이가 있음을 확인했다 — AI가 가./나./다. 사이를 `<br>` 대신 실제 줄바꿈 문자만으로 구분해 보낼 경우, HWPX는 정상이지만 화면은 모든 항목이 붙어 보이는 것이었다. `markdownOrHtmlToHtml`에 `normalizeBareLineBreaks` 함수를 추가해, 태그 경계(`<`, `>`)가 아닌 순수 텍스트 사이에 있는 줄바꿈만 `<br>`로 바꿔주도록 보정했다. 표의 `<tr>`·`<td>` 사이처럼 태그 바로 옆의 서식용 줄바꿈은 항상 `<`나 `>` 옆에 있으므로 건드리지 않아, 표 구조가 깨지거나 불필요한 줄바꿈이 끼어드는 부작용 없이 문제를 좁게 고쳤다. jsdom 단위 테스트 2건(개조식 항목 보정, 표 안 서식용 줄바꿈 미보정 확인)을 추가해 검증했다.

## 6. 향후 개선 방향

- 수업자료 AI의 슬라이드 전체 이미지 생성 기능은 아직 "구현중" 표시로 비활성화되어 있으며, 안정적인 이미지 생성 흐름이 확보된 뒤 정식 기능으로 전환한다.
- 업무추출 결과는 업무 종류별로 캘린더 제목과 날짜를 더 정밀하게 추출하도록 계속 개선한다.
- 학생 정보가 반영되는 기능은 계속해서 명시적 사용자 동작을 기준으로 제한한다.
- 상담 녹음 분석(Gemini 오디오 입력)은 개인정보와 API tier 정책 검토 후 도입을 검토한다.
- (코드 리뷰 후속) 학생 서술 생성 컴포넌트(교과·창체·스포츠클럽·생기부 등)에 중복된 생성 흐름 로직을 공용 훅으로 추출하고, 거대 컴포넌트(예산안작성 약 2,400줄, 교과 세특 약 1,960줄, 창의적 체험활동 약 1,530줄, 문서작성기 약 1,200줄)를 기능 단위로 분할하는 리팩터링을 검토한다. v1.18.0에서 4개 생성기에 학생 기록물 사진 분석과 생성 모델 표시 기능이 동일한 형태로 각각 추가되어 중복 규모가 이전보다 더 커졌다. 변경 범위가 커서 작업 전 별도 합의가 필요하다. (상담일지·수업관찰 화면의 다크 모드 적용과 Gemini API 키의 OS 안전 저장소(safeStorage) 이관은 v1.16.0에서, HWPX 문서 구조 보존 안정화와 수업 참여방(QR 채팅방)은 v1.14.0에서 정식 기능으로 완료)
