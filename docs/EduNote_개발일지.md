# EduNote 개발 일지

작성 기준: 2026년 5월 28일
작성 목적: 개발 보고서 작성용 요약 자료
대상 범위: 초기 구현부터 v1.7.9 릴리즈까지

## 1. 개발 개요

EduNote는 교사의 학생기록 작성, 교무행정 문서 작성, 수업자료 제작, 업무 추출을 하나의 데스크톱 앱에서 처리하기 위해 개발한 교육 업무 보조 도구이다. 초기 버전은 학생기록 AI와 교무 AI 기능을 중심으로 출발했으며, 이후 실제 학교 업무 흐름에 맞추어 수업자료 생성, 자료실, 학생 메모, 공문 요약, 캘린더 연동, 릴리즈 자동화 기능을 단계적으로 확장하였다.

개발 과정은 사용자가 실제로 앱을 실행하며 발견한 불편을 빠르게 반영하는 방식으로 진행되었다. 특히 Windows 환경에서 바로 실행할 수 있는 portable EXE 배포, API 키 사용성, 다크모드, 생성 중단, 동시 생성, 학교 현장 문서 양식 개선에 중점을 두었다.

### 1.1 업데이트 의도

EduNote의 업데이트는 단순 기능 추가보다 교사의 실제 업무 흐름을 줄이고, 생성 결과물을 학교 현장에서 바로 검토·수정할 수 있는 수준으로 다듬는 데 목적을 두었다. 초기에는 학생기록과 교무행정 문서 작성 보조에 집중했으나, 이후 수업자료 제작, 업무추출, 자료관리, 백업, 교육용 게임 실행 등 교사가 하루 업무 안에서 반복적으로 수행하는 작업을 하나의 앱 안에 모으는 방향으로 확장하였다.

주요 업데이트 의도는 다음과 같다.

- 학생기록, 상담, 수업관찰, 창체, 교과세특 작성 과정에서 교사가 문장 초안을 빠르게 확보할 수 있도록 지원
- 공문서, 계획서, 보고서, 품의서, 회의록, 공고문 등 학교 업무 문서의 형식과 문체를 실제 행정 문서에 가깝게 정리
- 수업자료 생성 결과를 슬라이드, 워크시트, 퀴즈, 수업 계획서, 교육용 게임 등 바로 활용 가능한 형태로 제공
- 학생 명단과 개인정보가 불필요한 기능에 자동 반영되지 않도록 제한하여 개인정보 최소화 원칙 반영
- 생성 결과물에서 AI가 작성한 느낌, 반복 문구, 불필요한 기호, 어색한 문체를 줄여 공적 문서 품질 개선
- Windows 교사 PC에서 설치 부담 없이 실행할 수 있도록 portable EXE 방식의 배포 유지

## 2. 사용 프로그래밍 언어 및 기술 스택

EduNote는 Windows 환경에서 교사가 별도 서버 구축 없이 실행할 수 있는 데스크톱 애플리케이션을 목표로 개발하였다. 이를 위해 웹 기반 UI의 빠른 개발성과 데스크톱 앱의 파일 저장·로컬 데이터 접근 기능을 함께 활용할 수 있는 Electron 기반 구조를 채택하였다.

### 2.3 프론트엔드 및 사용자 인터페이스

프론트엔드는 React 19와 TypeScript를 기반으로 구성하였다. 학생기록AI, 교무행정AI, 수업자료AI를 각각 독립 화면으로 나누고, 사용자가 메뉴를 이동해도 생성 작업이 유지되도록 상태 관리 구조를 설계하였다. 아이콘은 lucide-react를 사용해 메뉴, 버튼, 상태 표시를 직관적으로 표현하였다.

화면 스타일은 Tailwind CSS와 PostCSS를 사용하였다. 다크모드, 반응형 레이아웃, 입력 폼, 탭, 버튼, 알림 배지 등 반복되는 UI 요소를 일관된 스타일로 유지하는 데 활용하였다. 사이드바 메뉴는 섹션별로 드래그하여 순서를 변경할 수 있으며, 변경된 순서는 localStorage에 저장된다.

### 2.4 데스크톱 앱 구조

앱은 Electron 30 기반으로 구성하였다. Electron의 main process는 파일 저장, 폴더 선택, PDF 생성, 웹페이지 메타데이터 수집, 로컬 데이터 백업 같은 운영체제 연동 기능을 담당한다. renderer process는 React 화면과 사용자 상호작용을 담당하며, preload script를 통해 안전하게 Electron IPC 기능에 접근하도록 구성하였다.

### 2.5 AI 및 생성 서비스

AI 생성 기능은 Google Gemini API와 `@google/genai` 라이브러리를 기반으로 구현하였다. 무료 등급에는 `gemini-2.5-flash-lite`, 유료 등급에는 `gemini-2.5-pro` 모델을 사용한다. 학생기록, 교무행정 문서, 수업자료, 공문 요약, 이미지 생성 요청을 각각 다른 프롬프트와 시스템 지침으로 분리하였다.

### 2.6 로컬 데이터와 백업

사용자 설정은 electron-store를 활용해 로컬에 저장하였다. 학생 명단, 나만의 자료실, 학생 메모 등 계속 불러와야 하는 자료는 JSON 파일로 관리하였다. 전체 자료 백업 기능으로 기본 정보, 학생 명단, 자료실, 메모 데이터를 하나의 JSON 파일로 내보내고 다른 컴퓨터에서 불러올 수 있다. Gemini API 키는 백업 파일에 포함하지 않도록 설계하였다.

### 2.7 문서 생성 및 파일 처리

PDF 저장은 Electron의 `printToPDF` 기능을 활용하였다. HWPX 관련 실험에는 JSZip과 `@xmldom/xmldom`을 사용해 문서 내부 XML 구조를 분석하고 템플릿 치환 가능성을 검토하였다. HWPX 기능은 문서 구조 보존 안정성이 충분히 확보되기 전까지 `(구현중)`으로 표시하도록 정리하였다.

### 2.8 빌드와 배포

개발 빌드는 electron-vite와 Vite를 사용하였다. Windows 배포 파일은 electron-builder를 통해 portable EXE 형태로 패키징하였다. Git과 GitHub를 사용해 버전별 변경 이력을 관리했으며, 릴리즈 파일은 로컬에서 실제 EXE 빌드 검증 후 GitHub Releases에 직접 업로드하는 방식으로 운영하였다.

## 4. 주요 개발 성과

### 4.1 교사 업무 흐름 중심의 기능 통합

EduNote는 학생기록 작성, 상담일지, 수업관찰기록, 공문서 작성, 수업자료 생성, 업무추출을 하나의 앱 안에서 연결했다. 교사가 여러 웹서비스와 문서 도구를 오가며 처리하던 업무를 한 화면에서 시작하고 결과를 저장할 수 있도록 구성했다.

### 4.2 학교 현장 문서 양식 반영

공문서 작성기에는 공문, 계획서, 보고서, 품의서, 회의록, 홍보자료, 가정통신문, 문자 및 소통메시지, 공고문 등 학교에서 자주 쓰는 문서 유형을 반영했다. 공문서·품의서는 합쇼체, 계획서·보고서는 보고서체 문체를 분리하여 각 문서 유형에 맞는 언어 품질을 확보했다.

### 4.3 수업자료 제작 기능 확장

수업 슬라이드, 워크시트, 퀴즈, 수업 계획서를 생성하도록 확장했다. 생성 결과는 편집 가능하도록 개선했고, 수업 계획서는 표 중심으로 출력되도록 하여 인쇄와 검토에 적합하게 정리했다. 퀴즈는 객관식·주관식·OX 유형을 체크박스로 선택할 수 있으며, JSON 데이터와 고정 템플릿 방식으로 생성하여 모든 유형이 항상 안정적으로 동작한다.

### 4.4 개인정보와 사용자 통제 강화

학생 명단은 필요한 기능에서만 사용하도록 조정했다. 수업자료 생성의 추가 요청사항에는 학생 명단이 자동 입력되지 않으며, 사용자가 직접 불러왔을 때만 반영되도록 했다. 공문서 작성기에서는 학년도, 날짜, 소속기관만 문맥상 필요한 경우 참고하도록 제한했다.

### 4.5 배포와 유지보수 체계 정비

Windows 사용자가 별도 설치 없이 실행할 수 있도록 portable EXE 배포 방식을 유지했다. GitHub 릴리즈와 로컬 빌드 검증을 병행했으며, v1.7.2부터는 로컬에서 실제 EXE를 빌드한 뒤 GitHub 릴리즈에 직접 업로드하는 방식으로 배포 안정성을 높였다.

## 5. 최근 릴리즈 요약

v1.7.5는 학교 업무 문서의 문체와 형식을 정리한 릴리즈이다. 계획서와 보고서의 본문이 하나의 긴 문단처럼 이어지는 문제를 줄이고, 추진배경·목적·운영방침·기대효과와 운영 성과·제언을 `가. 나. 다.` 개조식으로 작성하도록 지침을 강화하였다.

v1.7.6은 앱의 시각적 일관성을 정리한 릴리즈이다. 실행파일 아이콘, 앱 내부 아이콘, 패키징 리소스의 PNG·ICO·SVG 파일을 모두 새 보라색 AI 노트 아이콘 기준으로 교체하였다.

v1.7.7은 생성 결과물의 문체와 수업자료 실행 흐름을 다듬은 릴리즈이다. 공문서와 품의서는 합쇼체, 계획서·보고서는 보고서체로 문체 지침을 분리하였다. 교육용 게임의 브라우저에서 열기 버튼을 화면 중앙에 크게 배치하고 동작을 보완하였다.

v1.7.8은 문서 서식과 API 상태 표시 경험을 개선한 릴리즈이다. 계획서·보고서 제목이 크게, 진하게, 가운데 정렬되도록 생성 지침을 강화하고, `가.`, `나.`, `다.` 항목이 반드시 줄바꿈되어 작성되도록 개선하였다. 표가 필요한 내용은 선이 있는 표로 생성되도록 보강하였다. 구현중 버튼은 오른쪽으로 배치하여 사용 가능한 버튼이 먼저 보이도록 정리하였다. API 일시 제한 상태를 왼쪽 하단에 점멸 표시하고, 마우스 오버 시 설명을 확인할 수 있도록 추가하였다.

v1.7.9는 보고서 생성 경험을 높인 릴리즈이다. 보고서 작성 화면에 주제, 대상, 예산/집행액, 운영 결과 요약, 추가 사항 입력칸을 추가하여 더 정확한 보고서 생성이 가능해졌다.

v1.8.0은 수업자료 기능을 개선한 릴리즈이다. 퀴즈에 객관식·주관식·OX 유형 선택 체크박스를 추가하고, 게임 제작 메뉴를 제거하였다. 계획서·보고서의 말머리 기호를 `1.` → `가.` → `1)` → `가)` 4단계 위계로 강화하였다.

v1.8.1은 퀴즈 신뢰성을 높인 릴리즈이다. 퀴즈 생성 방식을 AI가 HTML 코드를 직접 생성하는 방식에서 JSON 데이터만 생성하고 검증된 고정 템플릿에 주입하는 방식으로 전환하였다. 이로써 객관식·주관식·OX 퀴즈가 어떤 수업 내용으로 생성해도 항상 안정적으로 동작한다. 퀴즈 미리보기를 내부 iframe에서 `새 창에서 열기` 버튼으로 변경하였다.

v1.8.2는 업데이트 알림 버그를 수정한 릴리즈이다. 앱 메인 화면에서 새 버전이 릴리즈되어도 알림이 나타나지 않던 문제를 수정하였다. Node.js `https` 모듈 대신 `electron.net`을 사용하도록 변경하고, 버전 비교를 semver 숫자 비교 방식으로 전환하였다.

v1.8.4는 나만의 자료실 썸네일 버그를 수정한 릴리즈이다. YouTube 영상이나 웹페이지를 자료실에 추가할 때 썸네일·제목·설명이 불러와지지 않던 문제를 수정하였다. 메타정보 및 이미지 다운로드 핸들러 전체를 `electron.net.fetch()`로 교체하여 번들링 환경에서도 네트워크 요청이 정상 동작하도록 개선하였다.

## 6. 향후 개선 방향

- HWPX 관련 기능은 안정적인 문서 구조 보존 방식이 확보된 뒤 정식 기능으로 전환한다.
- 업무추출 결과는 업무 종류별로 캘린더 제목과 날짜를 더 정밀하게 추출하도록 개선한다.
- 학생 정보가 반영되는 기능은 계속해서 명시적 사용자 동작을 기준으로 제한한다.
- 릴리즈는 main 브랜치 push 시 GitHub Actions가 Windows EXE를 자동 빌드·배포한다.
