# 스킬마켓 구조를 다른 앱에 이식하기 — 에이전트 요청 가이드

> EduNote의 **스킬마켓**(구글 폼 등록 → 구글 시트 목록 → 드라이브 파일 가져오기) 구조를 다른 앱에 적용할 때, AI 코딩 에이전트(Claude Code 등)에게 그대로 붙여 넣을 수 있는 요청문과 체크리스트입니다.

---

## 0. 한 줄 요약

**"서버 없이 구글 폼·시트·드라이브만으로 사용자 간 공유 마켓을 만든다"** 가 핵심입니다.
에이전트에게는 ① 원본 구조(아래 1장), ② 대상 앱 정보(3장의 빈칸), ③ 보안 요구사항(4장)을 함께 주면 결과 품질이 크게 올라갑니다.

---

## 1. 원본 구조 요약 (에이전트에게 함께 전달할 참고 정보)

### 1-1. 데이터 흐름

```
[공유하는 사람]
 내 스킬 카드 → "공유" → ShareModal
   ① 스킬을 JSON(또는 HTML) 파일로 저장
   ② 사전 입력(prefill)된 구글 폼 열기 (이름·설명·유형·카테고리·작성자 자동 채움)
   ③ 사용자가 폼에서 파일을 드라이브에 업로드하고 제출
        ↓
 구글 폼 응답 → 구글 시트(응답 시트)에 한 행 추가

[가져오는 사람]
 "스킬마켓" 탭 진입
   ① 메인 프로세스가 시트를 CSV로 내려받음 (pub?output=csv → export?format=csv 순서로 시도)
   ② CSV 파싱 → 헤더 이름으로 열 위치 탐색 → MarketEntry 목록
   ③ 검색어·카테고리로 필터링해 카드 목록 표시
   ④ "가져오기" → 드라이브 공유 URL을 직접 다운로드 URL로 변환 → 메인 프로세스가 다운로드
   ⑤ JSON 검증(validateImportedTool) → 실패 시 HTML 앱이면 HTML로 감싸 검증
   ⑥ 이름 중복 확인 → 로컬 저장소에 추가(importedFromMarket: true) → "내 스킬" 탭으로 이동
   ⑦ 마켓 출신 HTML 앱은 실행 전 출처 확인창 표시
```

### 1-2. 관련 파일

| 역할 | 파일 | 핵심 요소 |
|---|---|---|
| 화면·로직 | `src/renderer/components/MyToolsScreen.tsx` | `MARKET_SHEET_ID`, `MARKET_FORM_URL`, `COL`, `CATEGORY_MAP`, `toDriveDownloadUrl`, `parseMarketCsv`, `loadMarket`, `handleImportFromMarket`, `MarketToolCard`, `ShareModal` |
| 데이터 타입 | `src/renderer/types.ts` | `CustomTool`, `importedFromMarket` 플래그 |
| 가져오기 검증 | `src/renderer/lib/security.ts` | `parseImportedTools`, `validateImportedTool`, `DANGEROUS_HTML_PATTERNS`, 크기 제한 |
| 네트워크(IPC) | `src/main/ipcHandlers.ts` | `data:fetch-market`(시트 CSV), `data:fetch-url-json`(파일 다운로드, 5MB 제한·리다이렉트 재검사) |
| URL 안전 검사 | `src/main/netGuard.ts` | `assertSafeUrl` (루프백·링크로컬 차단) |
| 브리지 | `src/preload/index.ts`, `src/preload/types.d.ts` | `fetchMarket`, `fetchUrlJson` |

### 1-3. 설계상 장점과 알려진 한계

| 구분 | 내용 |
|---|---|
| 장점 | 서버·DB·로그인 없이 운영 가능, 관리자는 시트에서 행 삭제만으로 검수·삭제 가능, 비용 0원 |
| 장점 | 헤더 이름 부분 일치로 열을 찾아 폼 질문 순서가 바뀌어도 동작 |
| 한계 | CSV 파서가 줄 단위로 나눠서 **셀 안에 줄바꿈이 있으면 행이 깨짐** → 이식 시 개선 권장 |
| 한계 | 폼 prefill의 `entry.숫자` ID가 코드에 하드코딩 → 폼 질문을 새로 만들면 ID 재확인 필요 |
| 한계 | 승인 절차 없음(등록 즉시 노출) → 필요하면 시트에 "승인" 열 추가 |
| 한계 | 다운로드 수·평점·버전 관리 없음 |

## 2. 사용 방법 (3단계)

1. **사전 준비(사람이 할 일)**: 구글 폼 만들기 → 응답 시트 연결 → 시트 "링크가 있는 모든 사용자 보기" 또는 "웹에 게시" → 폼 prefill 링크에서 `entry.xxxx` ID 확인
2. **3장의 요청문 빈칸 채우기** → 대상 앱 저장소에서 에이전트에게 붙여 넣기
3. **5장 체크리스트로 결과 검수**

> 원본 코드를 에이전트가 직접 읽게 하면 정확도가 높아집니다. 대상 앱 저장소에 `MyToolsScreen.tsx`, `security.ts`, `ipcHandlers.ts`의 해당 부분을 `reference/` 폴더로 복사해 두거나, 1장 내용을 요청문에 함께 붙이세요.

## 3. 복붙용 요청문

### 3-1. 기본 요청문 (가장 추천)

```markdown
# 작업 요청: "공유 마켓" 기능 추가

## 목표
이 앱의 [공유 대상: 예) 수업 템플릿 / 프롬프트 / 체크리스트]을 사용자끼리 공유할 수 있는
"[마켓 이름: 예) 템플릿마켓]" 탭을 추가해 주세요.
별도 서버 없이 구글 폼(등록) + 구글 시트(목록) + 구글 드라이브(파일 저장)로 운영합니다.

## 참고 구조
아래는 다른 앱(EduNote 스킬마켓)에서 이미 검증한 구조입니다. 같은 흐름을 따르되,
이 저장소의 기존 코드 스타일·폴더 구조·상태 관리 방식에 맞춰 구현해 주세요.

(여기에 이 문서 1장 "원본 구조 요약"을 붙여 넣기)

## 대상 앱 정보
- 앱 형태: [Electron / React 웹앱(Vite) / Next.js / Google Apps Script 웹앱 / 기타]
- 공유 대상 데이터 타입: [기존 타입 이름과 위치, 예) src/types.ts 의 Template]
- 로컬 저장 방식: [localStorage / electron-store / IndexedDB / Firestore 등]
- 기존 "내 목록" 화면: [파일 경로]
- 카테고리: [예) 국어, 수학, 생활지도, 기타]

## 운영 설정값 (상수로 분리)
- 시트 ID: [시트 URL의 /d/ 와 /edit 사이 값]
- 폼 URL: [https://docs.google.com/forms/d/e/.../viewform]
- 폼 질문 ↔ prefill entry ID:
  - 이름: entry.[ ]
  - 설명: entry.[ ]
  - 카테고리: entry.[ ]
  - 작성자/소속: entry.[ ]
  - 한 마디: entry.[ ]
- 응답 시트 열 이름: 타임스탬프 / [이름] / [설명] / [카테고리] / [작성자] / [소속] / [한 마디] / [파일]

## 구현 범위
1. 마켓 목록 탭: 시트 CSV 불러오기, 검색, 카테고리 필터, 새로고침, 로딩·오류·빈 목록 상태
2. 가져오기: 드라이브 공유 URL → 직접 다운로드 URL 변환, 다운로드, 스키마 검증, 이름 중복 확인,
   내 목록에 추가(출처 플래그 `importedFromMarket: true`), 성공 시 내 목록 탭으로 이동
3. 공유하기 모달: 파일로 내보내기 + prefill된 구글 폼 열기, 작성자·소속은 다음번을 위해 기억
4. 시트 열 매칭: 정확히 일치 → 키워드 부분 일치 순으로 찾기, 파싱 실패 시 감지된 열 이름을 화면에 표시

## 반드시 지킬 보안 요구사항
- 외부 데이터는 전부 신뢰하지 않는다: 가져온 파일은 타입·필수 필드·길이를 검증한 뒤에만 저장
- 다운로드 URL은 http(s)만 허용, 리다이렉트마다 재검사, 응답 크기 상한(예: 5MB)과 타임아웃 적용
- [Electron이면] 네트워크 요청은 메인 프로세스에서만, 렌더러는 preload로 노출된 함수만 호출
- [웹앱이면] CORS 문제는 우회 프록시로 해결하지 말고, 시트 "웹에 게시" CSV 또는 Apps Script 엔드포인트 사용
- HTML/스크립트를 포함할 수 있는 데이터라면 외부 script src 차단 + 실행 전 출처 확인창
- 학생 개인정보가 마켓 파일에 포함되지 않도록 공유 모달에 안내 문구 표시

## 개선 요청 (원본의 한계 보완)
- CSV 파서는 셀 안의 줄바꿈과 따옴표 이스케이프("")를 올바르게 처리하도록 구현
- 파싱·URL 변환·검증 함수는 화면 컴포넌트에서 분리해 순수 함수로 만들고 단위 테스트 작성

## 작업 방식
1. 코드를 수정하기 전에 이 저장소 구조를 파악하고, 어떤 파일을 새로 만들고 고칠지 계획을 먼저 보여 주세요.
2. 기존 기능과 디자인을 깨지 않도록 최소 변경으로 구현하세요.
3. 완료 후 타입 검사·테스트를 실행하고 결과를 알려 주세요.
4. 마지막에 "운영자가 해야 할 구글 폼·시트 설정 절차"를 체크리스트로 정리해 주세요.
```

## 4. 에이전트에게 꼭 강조할 포인트

1. **설정값은 상수로 분리**: 시트 ID, 폼 URL, entry ID, 열 이름 → 한 파일(`marketConfig.ts` 등)에 모으기
2. **검증 없이 저장 금지**: 원본의 `validateImportedTool`처럼 타입·필수 필드·크기 검사 필수
3. **출처 표시**: 가져온 항목에 `importedFromMarket` 같은 플래그를 남겨 실행·편집 시 경고에 활용
4. **오류 메시지를 사용자 언어로**: "시트가 공개되어 있지 않습니다", "파일이 공개 설정인지 확인해 주세요"처럼 원인과 해결을 함께
5. **계획 먼저, 구현 나중**: 대상 앱 구조가 다르므로 바로 구현시키지 말고 계획을 확인한 뒤 진행

## 5. 결과 검수 체크리스트

### 기능
- [ ] 마켓 탭 진입 시 목록이 자동으로 불러와진다
- [ ] 새로고침 버튼으로 다시 불러올 수 있다
- [ ] 검색(이름·설명·작성자)과 카테고리 필터가 동작한다
- [ ] 가져오기 후 내 목록에 추가되고 내 목록 탭으로 이동한다
- [ ] 같은 이름은 중복 추가되지 않고 안내가 뜬다
- [ ] 공유 모달에서 폼이 이름·설명·카테고리·작성자가 채워진 상태로 열린다
- [ ] 설명에 줄바꿈·쉼표·따옴표가 있어도 목록이 깨지지 않는다

### 오류 상황
- [ ] 시트 비공개 → 원인과 해결 방법 안내
- [ ] 드라이브 파일 비공개 → "공개 설정 확인" 안내
- [ ] 형식이 잘못된 파일 → 저장하지 않고 이유 표시
- [ ] 네트워크 끊김·타임아웃 → 무한 로딩 없이 오류 표시

### 보안
- [ ] 외부 URL은 http(s)만 허용되고 크기·시간 제한이 있다
- [ ] 가져온 데이터는 검증 함수를 통과해야만 저장된다
- [ ] 실행 가능한 콘텐츠(HTML 등)는 출처 확인창이 뜬다
- [ ] 공유 모달에 개인정보 포함 금지 안내가 있다
- [ ] API 키·비밀값이 코드나 시트에 노출되지 않는다

### 코드 품질
- [ ] 파싱·변환·검증 함수가 분리되어 있고 단위 테스트가 있다
- [ ] 타입 검사·테스트가 통과한다

## 6. 운영자 사전 준비 체크리스트 (구글 폼·시트)

1. 구글 폼 생성, 질문: 이름(단답) / 설명(장문) / 카테고리(객관식) / 작성자·소속(단답) / 한 마디(단답) / 파일(파일 업로드)
2. 응답 탭 → 스프레드시트 연결
3. 시트 공유: "링크가 있는 모든 사용자 – 뷰어" (또는 파일 → 공유 → 웹에 게시 → CSV)
4. 파일 업로드 폴더(드라이브)도 "링크가 있는 모든 사용자 – 뷰어"로 공유 (안 하면 가져오기 실패)
5. 폼 우측 상단 ⋮ → "미리 채워진 링크 받기" → 각 칸에 값을 넣고 링크 생성 → URL의 `entry.숫자` 기록
6. 시트 ID, 폼 URL, entry ID를 3장 요청문에 기입
7. 부적절한 등록은 시트에서 해당 행을 삭제하면 목록에서 사라짐 (승인제가 필요하면 "승인" 열 추가 요청)
