## 1. 제품 개요

### 1.1 기본 정보

| 항목 | 내용 |
|------|------|
| 제품명 | EduNote |
| 버전 | v1.0.0 (MVP, 최소 기능 제품) |
| 플랫폼 | Windows 데스크톱 |
| 배포 형태 | 설치 불필요한 단독 실행 파일 (Portable EXE) |
| 작성 시점 | 개발 시작 전 기획 단계 |

### 1.2 제품 목적

EduNote는 한국 초·중·고 교사가 학기마다 반복적으로 작성해야 하는 학생생활기록부(이하 학생기록) 문장 작성에 드는 시간과 노력을 AI(인공지능)를 활용해 크게 줄여주는 Windows 전용 데스크톱 도우미 앱이다.

v1.0.0은 학생기록 작성 지원이라는 핵심 문제 하나에 집중하는 MVP(Minimum Viable Product, 최소 기능 제품)로 출시한다. 실제 교사의 손에 먼저 닿게 하고, 피드백을 받아 기능을 확장하는 방식을 택한다.

### 1.3 제품 비전

> "모든 교사가 행정 부담 없이 교육에 집중할 수 있는 환경을 만든다."

EduNote는 복잡한 설치나 회원가입 없이 학교 PC에서 바로 실행되는 실용적인 도구를 지향한다. AI 기술을 교사의 실제 업무 흐름에 맞게 설계하여, IT에 익숙하지 않은 교사도 쉽게 활용할 수 있도록 한다.

## 2. 문제 정의

### 2.1 배경

한국의 교사는 학기마다 담당 학생 전원에 대한 학생생활기록부를 작성해야 한다. 생활기록부는 학생의 학교생활 전반을 기록하는 공식 문서로, 상급학교 진학이나 취업에 직접 영향을 미친다. 따라서 교사는 형식과 내용 모두에 신중하게 작성해야 하는 부담을 안고 있다.

### 2.2 교사가 겪는 현실적 어려움

학생기록 작성에서 교사가 반복적으로 겪는 어려움은 다음과 같다.

| 어려움 | 구체적인 상황 |
|--------|-------------|
| 반복 작성의 피로 | 학생 1인당 여러 항목을 써야 하며, 담당 학생이 20~30명이면 같은 작업을 수십 번 반복해야 한다 |
| 문장 구성의 어려움 | 교육부가 정한 기재요령(작성 방법)에 맞는 문장을 처음부터 만들어야 한다 |
| 글자 수 제한 관리 | 항목마다 글자 수 제한이 있어, 내용을 넣고 빼며 조정하는 데 시간이 걸린다 |
| 반복·복사의 한계 | 이전 학기 기록을 복사해서 수정하는 방법을 쓰지만, 개별 학생 특성을 반영하는 데 여전히 시간이 필요하다 |
| 집중 마감 압박 | 학기 말에 수업·행사·평가 등 다른 업무와 동시에 마감이 겹쳐 극심한 시간 압박을 받는다 |

### 2.3 항목별 작성 부담

교사가 학생 1인당 작성해야 하는 주요 항목은 다음과 같다.

| 항목 | 설명 |
|------|------|
| 행동특성 및 종합의견 | 학생의 학교생활 전반을 담임교사가 종합적으로 서술 |
| 교과 세부능력 및 특기사항(세특) | 각 교과목에서의 학습 활동과 특이사항을 교과 담당교사가 서술 |
| 학교스포츠클럽 특기사항 | 스포츠클럽 활동 내용을 담당교사가 서술 |
| 창의적 체험활동 특기사항 | 자율·동아리·봉사·진로 활동 내용을 담당교사가 서술 |

학생 30명을 담당하는 교사가 항목 하나당 평균 10분을 쓴다고 가정하면, 4개 항목만으로도 한 학기에 최소 20시간 이상이 학생기록 작성에 소요된다. 실제로는 검토·수정 시간까지 포함하면 훨씬 더 많은 시간이 들어간다.

### 2.4 기존 해결 방법의 한계

| 기존 방법 | 한계 |
|-----------|------|
| 매번 직접 작성 | 가장 많은 시간과 노력이 들어간다 |
| 이전 기록 복사·수정 | 개별 학생 특성 반영이 부족하거나, 이전 기록과 유사한 문장이 반복될 수 있다 |
| 온라인 문장 모음집 참고 | 공통 문장을 모아놓은 자료를 참고하지만, 개별 학생에 맞게 수정하는 작업이 여전히 필요하다 |

## 3. 타깃 사용자

### 3.1 주 사용자

한국 초등학교·중학교·고등학교에 재직 중인 교사

### 3.2 페르소나 — "한국 현장 교사"

| 특성 | 설명 |
|------|------|
| IT 친숙도 | 비전문가 수준. 스마트폰·PC 기본 사용은 가능하나, 개발·기술 지식은 없다 |
| 사용 기기 | 학교 또는 개인 Windows PC |
| 담당 학생 수 | 학급당 20~30명 |
| 업무 패턴 | 학기 중 수업·행정 업무가 겹쳐 매우 바쁘며, 학기 말에 특히 피크가 온다 |
| 주요 고충 | 반복적인 문서 작성에 드는 시간, 학기 말 마감 압박 |
| 사용 맥락 | 교무실 PC, 저녁 및 주말 개인 PC |

### 3.3 사용 시나리오

담임교사 A씨는 학기 말이 다가오면서 30명 학생의 학생기록 작성을 시작한다. 학생별로 메모해둔 특성 내용을 보며 항목마다 문장을 직접 구성하는 데 며칠이 걸린다. EduNote를 사용하면 각 학생의 특성을 메모 형식으로 입력한 뒤 AI가 초안을 생성하면, A씨는 초안을 검토하고 필요한 부분만 수정하여 학교 시스템에 붙여넣는 방식으로 작업 시간을 크게 줄일 수 있다.

## 4. 해결 방향

### 4.1 핵심 접근법

EduNote는 교사가 완성된 문장을 처음부터 작성하는 대신, AI가 초안을 생성해 주고 교사가 검토·수정하는 방식으로 업무 흐름을 바꾼다.

```
[교사 입력] → [AI 초안 생성] → [교사 검토·수정] → [학교 시스템에 복붙]
```

### 4.2 설계 원칙

- 복잡하지 않게: 설치 없이 EXE 파일 하나로 실행된다.
- 어렵지 않게: IT 비전문가인 교사가 설명서 없이도 사용할 수 있는 화면 구성을 지향한다.
- 안전하게: 학생 개인정보와 API 키는 사용자 PC 밖으로 불필요하게 나가지 않는다.
- 빠르게: AI 초안 생성 후 교사가 추가로 수정하는 시간이 처음부터 작성하는 것보다 현저히 짧아야 한다.

## 5. 핵심 기능 요구사항

아래 각 기능은 사용자 스토리와 수락 기준(Acceptance Criteria) 형식으로 기술한다.

> 사용자 스토리 형식: "나는 [역할]로서, [목표]를 위해 [기능]이 필요하다."
> 수락 기준: 해당 기능이 제대로 동작한다고 판단하는 구체적인 조건 목록

---

### 5.1 학생기록 AI — 핵심 기능

#### 5.1.1 행동특성 및 종합의견 생성

**사용자 스토리**
나는 담임교사로서, 학기말 생활기록부 마감 부담을 줄이기 위해 학생별 행동특성 및 종합의견 초안을 AI가 생성해 주는 기능이 필요하다.

**수락 기준**
- 학생 이름, 성별, 학년, 교사가 메모한 학생 특성을 입력하면 행동특성 및 종합의견 초안이 생성된다.
- 생성된 결과를 화면에서 바로 수정할 수 있다.
- 결과물을 클립보드로 복사하거나 TXT 파일로 저장할 수 있다.
- 학생 개인정보는 최소한만 입력받으며, AI 생성 요청 이외의 목적으로 외부 서버에 전송하지 않는다.

#### 5.1.2 교과 세부능력 및 특기사항(세특) 생성

**사용자 스토리**
나는 교과 담당교사로서, 수십 명 학생 각각의 세특을 작성하는 시간을 줄이기 위해 AI가 초안을 작성해 주는 기능이 필요하다.

**수락 기준**
- 교과목, 단원명, 학생 수행 내용 및 특이사항을 입력하면 세특 초안이 생성된다.
- 생성 결과를 복사하거나 TXT 파일로 저장할 수 있다.

#### 5.1.3 학교스포츠클럽 특기사항 생성

**사용자 스토리**
나는 스포츠클럽 담당교사로서, 참여 학생의 특기사항 기재 시간을 단축하기 위해 AI 초안 생성 기능이 필요하다.

**수락 기준**
- 종목, 활동 내용, 학생 특성을 입력하면 특기사항 초안이 생성된다.
- 결과를 복사하거나 TXT 파일로 저장할 수 있다.

#### 5.1.4 창의적 체험활동 특기사항 생성

**사용자 스토리**
나는 담임교사로서, 자율·동아리·봉사·진로 등 창의적 체험활동 특기사항 기재 시간을 줄이기 위해 AI 초안 생성 기능이 필요하다.

**수락 기준**
- 활동 영역(자율·동아리·봉사·진로), 활동 내용을 입력하면 특기사항 초안이 생성된다.
- 결과를 복사하거나 TXT 파일로 저장할 수 있다.

---

### 5.2 설정

**사용자 스토리**
나는 교사로서, AI 기능을 사용하기 전에 내 Gemini API 키를 등록하고 기본 정보(학교급, 이름)를 입력하고 싶다.

**수락 기준**
- Gemini API 키를 입력하고 저장할 수 있다.
- API 키는 로컬 기기에 저장되며, 외부 서버로 전송되지 않는다.
- 학교급(초등·중학교·고등학교)을 선택할 수 있다.
- 교사 이름과 소속기관(학교명)을 입력할 수 있다.
- 학생 명단(이름 목록)을 입력할 수 있으며, AI 생성 시 학생 정보 입력에 활용된다.
- 입력한 설정 값은 앱을 다시 실행해도 유지된다.

---

### 5.3 결과 출력

**사용자 스토리**
나는 교사로서, AI가 생성한 결과를 화면에서 확인하고 학교 시스템에 옮겨쓰거나 파일로 저장하고 싶다.

**수락 기준**
- AI 생성 결과가 화면에 표시된다.
- "복사" 버튼을 누르면 결과 텍스트가 클립보드에 복사된다.
- TXT 파일로 저장할 수 있다.

---

### 5.4 앱 기반

**수락 기준**
- Windows 10, Windows 11(64비트) 환경에서 실행된다.
- 별도 설치 과정 없이 EXE 파일을 실행하는 것만으로 앱이 동작한다(Portable EXE).
- 사이드바 메뉴 구조로 각 기능 화면에 접근할 수 있다.

## 6. 비기능 요구사항

비기능 요구사항이란 "무엇을 하는가"가 아니라 "어떻게 동작해야 하는가"에 관한 조건이다.

### 6.1 운영 환경

| 항목 | 요구사항 |
|------|---------|
| 지원 OS | Windows 10, Windows 11 (64비트) |
| 설치 방식 | Portable EXE (설치 불필요, 파일 하나로 실행) |
| 인터넷 연결 | AI 생성 기능 사용 시 필수 |

### 6.2 보안 및 개인정보

| 항목 | 요구사항 |
|------|---------|
| API 키 저장 | 로컬 기기에 저장. 외부 서버로 전송하지 않는다 |
| 학생 개인정보 | 최소 사용 원칙 적용. AI 생성 요청 외의 목적으로 외부에 전송하지 않는다 |
| 외부 전송 데이터 | AI 생성 요청 내용은 Google Gemini API로 전달된다. 그 외 데이터는 외부로 나가지 않는다 |

### 6.3 응답 시간 목표

| 항목 | 목표 |
|------|------|
| AI 생성 첫 응답 시작 | 요청 후 30초 이내 (정상 네트워크 환경 기준) |
| 앱 실행(로딩) 시간 | 5초 이내 |

### 6.4 안정성

- 주요 기능(AI 생성, 파일 저장) 사용 중 앱이 갑자기 종료되는 현상(크래시)이 발생하지 않아야 한다.
- AI 생성 실패(네트워크 오류, API 한도 초과 등) 시 교사가 이해할 수 있는 오류 메시지를 표시해야 한다.

## 7. 기술 결정 사항 및 근거

### 7.1 Electron — Windows 데스크톱 앱 프레임워크

| 항목 | 내용 |
|------|------|
| 선택 기술 | Electron (웹 기술 기반 데스크톱 앱 제작 도구) |
| 선택 이유 | React·TypeScript 등 웹 기술로 Windows 데스크톱 앱을 만들 수 있어 개발 속도가 빠르다. 교사 대상 앱 특성상 복잡한 네이티브 기능이 불필요하며, Electron은 이 수준의 앱에 적합하다 |
| 대안 | .NET WPF(Windows 전용, 학습 곡선 높음), Tauri(경량이지만 생태계가 상대적으로 작음) |

### 7.2 Google Gemini API — AI 생성 엔진

| 항목 | 내용 |
|------|------|
| 선택 기술 | Google Gemini API |
| 선택 이유 | 무료 티어(Free Tier)를 제공하여 소규모 교육용 앱에서 사용자가 별도 비용 없이 AI 기능을 체험할 수 있다. 교사가 직접 API 키를 발급받아 앱에 입력하는 방식이므로, EduNote 운영자 측 API 비용이 발생하지 않는다 |
| 대안 | OpenAI GPT API(무료 티어 없음, 유료), 로컬 LLM(학교 PC 사양 제약으로 현실적이지 않음) |

### 7.3 Portable EXE — 설치 없는 배포 방식

| 항목 | 내용 |
|------|------|
| 선택 방식 | Portable EXE (설치 과정 없이 EXE 파일 실행만으로 동작) |
| 선택 이유 | 학교 PC는 보안 소프트웨어나 IT 관리 정책으로 인해 새 프로그램 설치가 어려운 경우가 많다. Portable EXE는 설치 없이 실행할 수 있어 이 제약을 우회할 수 있다. 배포도 파일 하나를 전달하면 되므로 단순하다 |

## 8. 제약 사항 및 리스크

### 8.1 Gemini API 무료 한도 리스크

| 항목 | 내용 |
|------|------|
| 리스크 | 무료 티어에는 분당 요청 수, 일일 요청 수 제한이 있다. 학기 말처럼 한꺼번에 많은 생성 요청을 보내면 한도를 초과할 수 있다 |
| 영향 | 한도 초과 시 일시적으로 AI 생성 기능을 사용할 수 없다 |
| 대응 방안 | 오류 메시지에 한도 초과 안내와 유료 전환 방법을 안내한다. 요청을 한꺼번에 보내지 않도록 UI에서 단건 생성 방식을 기본으로 한다 |

### 8.2 학교 보안 소프트웨어 간섭 리스크

| 항목 | 내용 |
|------|------|
| 리스크 | 일부 학교의 방화벽(외부 인터넷 차단 장치)이나 보안 소프트웨어가 Electron 앱 실행이나 Gemini API 연결을 차단할 수 있다 |
| 영향 | 해당 환경에서는 AI 기능이 동작하지 않는다 |
| 대응 방안 | 연결 실패 시 명확한 안내 메시지를 표시한다. 이는 EduNote 자체에서 해결할 수 없는 학교 환경 제약임을 사용자에게 안내한다. 개인 핫스팟(스마트폰 인터넷 공유)으로 우회 사용이 가능함을 안내한다 |

### 8.3 AI 생성 품질 편차 리스크

| 항목 | 내용 |
|------|------|
| 리스크 | AI가 생성하는 문장의 품질이 입력 내용의 충실도, 학생 특성의 복잡도에 따라 달라질 수 있다. 일부 경우 교육부 기재요령 형식과 맞지 않는 문장이 나올 수 있다 |
| 영향 | 교사가 AI 결과를 그대로 쓰지 못하고 직접 수정해야 하는 경우가 생긴다 |
| 대응 방안 | EduNote는 AI 결과를 "완성본"이 아닌 "초안"으로 명확히 안내한다. 교사가 반드시 검토·수정 후 사용하도록 UI와 안내 문구에서 강조한다 |

### 8.4 Mac·Linux 미지원

- EduNote v1.0.0은 Windows 전용 앱이다.
- 학교 현장의 주요 업무 환경이 Windows PC이므로, MVP 단계에서는 Windows에만 집중한다.

### 10.1 학생기록 AI 확장 (v1.x 검토)

| 생활기록부 기재요령 Q&A | 기재요령 관련 질문을 AI에게 물어볼 수 있는 챗봇 기능을 제공한다 |

| 기능 | 설명 |
|------|------|

| 공문 업무 추출 | 수신한 공문 내용을 붙여넣으면 처리 항목과 마감일을 자동으로 추출한다 |
